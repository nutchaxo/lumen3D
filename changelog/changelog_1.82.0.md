# Changelog v1.82.0 (Web Platform) — audit wave: performance, security, functionality, optimisation and UI/UX

## [OPTIMIZED]
- **Graphs compute in a worker, one query at a time**: the Graphs plugin now runs its queries in a worker of its own. A table crosses to it once, and each query sends only its settings. A newer query replaces one still waiting, so dragging the threshold slider no longer freezes the 3D view, and in Compare the panels no longer pile queries onto the page's one shared thread. The binning of an axis is reused across queries, which roughly halves the cost of a threshold change on a full voxel table.
- **Closing Graphs frees its memory**: closing the Graphs panel now drops the lossless table it read (which can exceed 100 MB on a large volume), its position columns, the worker copy and the Plotly plot; reopening reads the data again. A language switch no longer leaves the old plot and its resize handler alive.
- **Plotly loaded once per page**: a new core loader `PluginRegistry.loadVendor('plotly')` holds the library's path and SRI hash in one place, and Graphs and Tracking charts share it. Two plugins opening at the same time no longer download and parse plotly.min.js twice; on an older core the plugins join a load already in flight instead of starting a second one.
- **Plugin loading costs fewer requests**: the viewer, 2D and Compare pages read `version.json` (one hash per shipped file, about 60 KB) only when a plugin has no server vouch (a static host), and every read of it is revalidated (`no-cache`). The trust check reads plugin scripts with HTTP revalidation (a 304 reuses the cached copy) instead of bypassing the cache, while the SHA-256 check against the server's vouch still covers the exact bytes that run. A plugin's `lang/<code>.json` files are taken from the bytes already fetched for that check instead of being requested again. Every viewer boot and Compare panel used to download all plugin JavaScript again while the first bricks were loading.
- **Cheaper plugin discovery on every page boot**: `/api/plugins` reuses its walk of `js/modules` for 2 seconds and keeps the compressed answer instead of re-gzipping it per request. Approving, revoking, disabling, installing or uninstalling a plugin still takes effect on the next request.
- **HTML pages compressed by the Python server**: top-level pages and the 404 page are now gzip-compressed when the browser accepts it (with `Vary: Accept-Encoding`), like Apache's DEFLATE. viewer.html drops from about 42 KB to about 8 KB per load.
- **Pages paint before the vendor libraries load**: lucide (every public page) and three.js (viewer) now load at the end of the body, just before the page's own scripts, instead of blocking the first paint from the head. The load order and SRI pins are unchanged, also in release bundles.
- **Faster first paint of the landing, 2D and Compare pages**: the English file and the saved or browser language are fetched while the language list is still being discovered, concurrent requests for the same language file share one download, and the catalog request starts beside the instance config and translations instead of after them. A French visitor saves two to three round trips before the page can render.
- **No stale cache stamps in a checkout**: the source HTML pages no longer carry hand-written `?v=` stamps, which made the dev server serve an edited stylesheet, script, decode worker or admin tab as immutable for a week. Releases still stamp every asset URL with the version, and a test keeps hand stamps from coming back.
- **Composed bricks spread over the whole decode-worker pool**: each brick now reserves its worker while it waits for its bytes, so the bricks a quality load or timepoint switch starts together go to different workers instead of all queueing on the first one. The first picture of a load and of a timelapse frame arrives sooner.
- **Split (RG8 + R8) atlas bricks are split in the decode worker**: on GPUs without RGTC (software renderers, mobile, GPU compression off), a 3-channel brick now reaches the page as its two texture planes, so the main thread no longer runs a per-voxel loop for every streamed brick. Bricks assembled on the main thread reuse two scratch planes instead of allocating about 0.86 MB each.
- **Slice preview reads back without a second copy**: the slice tool's preview reads the GPU frame straight into the image it puts on the canvas. A drag frame no longer copies 4 MB (16 MB for the sharp pass) on the main thread, and about 20 MB of duplicate memory is freed while the tool is open.
- **Compare channel sync no longer rebuilds sibling sidebars**: a channel edit relayed from another panel now updates that one channel in place (`ChannelPanel.patchChannel`) instead of rebuilding every channel's markup, icons and histograms once per frame of a drag. A soloed channel in a sibling stays soloed unless the edit changes its visibility.
- **Studio decode workers shared out in Compare and released when idle**: the plane and cut-brick decode pools behind the Studio's native pass now get each Compare panel's share of the processor cores, like the brick decoders, and are terminated a few seconds after the last decode instead of staying alive for the whole session.
- **The tracking surface model is no longer downloaded again on every visit**: the Surface layer of a tracked timelapse makes one request for `model.glb` through the browser cache with revalidation, so an unchanged model comes back as a 304 instead of about 20 MB. The request for a compressed copy that the pipeline never writes, which always returned 404, is gone (tracking-surface 1.0.4).
- **One implementation of plugin sidebar sections and canvas panels**: the volume viewer and the 2D page now share `Utils.mountPluginSection`, `Utils.mountPluginPanel` and `Utils.datasetBaseUrl`. A section added twice on the 2D page now replaces the first instead of duplicating it and its id, and the viewer's handle also offers `section`, so a plugin gets the same contract on both pages.
- **One stage rule for display and sorting**: the explorer's stage sort now uses the same function that formats a stage for display (new `Utils.stageNumber`). `Catalog` used to have its own copy of the rule, so editing only one copy could make a dataset show as E18.5 but sort as E1.85.
- **Large imports plan and finish files faster**: planning a browser import numbers new files in constant time instead of re-scanning the whole journal for each file, so a 20,000-file timelapse drop plans in under half a second instead of about a minute on the Python server and no longer exceeds `max_execution_time` on PHP hosts. When the chunk log already records every chunk of a file, completing it syncs that log and leaves the journal as it is (the log is compacted at 4,096 records), which halves the dataset-lock time per finished file on both backends.
- **PHP admin requests no longer re-read every dataset's metadata**: the metadata identity repair pass is skipped while the published tree's stat signature is unchanged since the last clean pass. Each uploaded file of a browser import and each Datasets or Integrity click used to read and decode every `metadata.json` on the host. A changed, new or failed-to-repair dataset is still checked on the next request.
- **Admin Plugins and Statistics tabs load once**: opening either tab for the first time sent its requests twice (the plugin list, the signed catalog check, the statistics), because both the tab's setup and its activation fetched. Only the activation fetches now, and a refresh or approval that arrives while a load is running is queued as one follow-up request.
- **Dataset updates no longer slow down quadratically on large datasets**: the server executor keeps its own schedule of the units still to start and journals finished units in batches (every 32 units or every second, always before it answers), instead of rescanning every unit and rewriting the whole journal after each one. Batched browser requests read the journal once per request instead of once per unit. A 100-frame timelapse (about 140,000 units) no longer spends hours on bookkeeping.
- **Faster XZ/YZ stage of the format-5 conversion on the server**: XZ/YZ units whose bands fall in the same row or column of plane tiles now run as one task that reads and decodes each tile once, instead of once per unit. A group is capped at 256 MiB of bands, and all running XZ/YZ tasks together at 512 MiB. The packs are byte-identical and the journal is unchanged.
- **Browser dataset conversion holds less memory per batch**: a migration worker drops each byte run it read once the last unit of its batch that lists it is done. Runs fetched after the prefetch are kept for a later unit only within the same 48 MiB budget, as their own copy, so a batch of neighbouring units no longer keeps the compressed input of all sixteen units until it ends. This removes the risk of running out of memory on large volumes with several workers.
- **Leaner cached migration plans**: the Python server's cached plan for a format-1/2 dataset no longer keeps the manifest's per-brick pack index, and the tree's brick index shares one path per pack file. Opening the Data updates tab no longer leaves hundreds of MB held by the server process for as long as it runs.

## [FIXED]
- **A signed-out admin session no longer reaches the dataset API on PHP hosts**: `api/datasets.php` accepted any session still carrying the login flag, so a cookie left after a password change, or one older than the 8-hour lifetime, could still list hidden datasets, edit, delete and empty the trash. It now applies the same expiry and credential check as every other admin endpoint and the Python server.
- **PHP first-run setup refuses cross-site requests**: on a PHP host the setup action accepted a text/plain or cross-site POST, so a hostile page visited before the wizard was finished could create the admin account with a password of its choosing. It now requires a same-origin JSON request like login and logout, as the Python server already did.
- **PHP first-run setup can no longer lock the operator out**: the admin credential is written in full to a temporary file and hard-linked into place, then read back before setup answers success. A full disk or a request killed mid-write used to leave an empty credential that blocked both login and setup until someone deleted it over SFTP. The Python server already worked this way.
- **Download counts can no longer be inflated by a request loop**: a full GET of a file under a dataset's `download/` folder is now counted through a per-client and global token bucket (same limits as the visit/view beacon, its own table on both servers). A flood can no longer forge the Downloads figures or force a `stats.json` rewrite on every request on PHP hosts. The file itself is always served.
- **Plugin publisher refuses unsafe ids and versions**: `tools/publish_plugin.py` and `tools/build_plugin_release.py` check a plugin.json id against the installer's own folder-name rule, and the version against a plain file-name rule, before the signing seed is read or any folder is touched. An id of `.` or `..` used to make the publisher delete every published plugin or the whole `marketplace/` folder.
- **Colours from a link, workspace or metadata cannot add CSS**: the measurement store accepts only `#rgb` to `#rrggbbaa` colours and replaces anything else with the default red, and the measure-distance list runs the same check, so a colour carried by a workspace file or a shared `#state=` link can no longer add CSS (for example a full-page invisible overlay) to the measurement list. Graphs likewise keeps only hex channel colours from `metadata.json`, both when its variables are built and when the Y-variable chip is drawn.
- **Graphs state from a link or workspace cannot inject page content**: a shared viewer link or a restored workspace could write arbitrary markup into the Graphs controls through the bin count or the threshold. Restored settings are now reduced to known fields with valid values before they are shown or written back to the address bar.
- **Page-editor settings no longer vanish on PHP hosts**: `api/site.php` stored every empty JSON object as `[]` (column and widget props, empty maps in instance.json/theme.json, drafts), so a column's alignment, padding or card style set afterwards was dropped silently at the next save or publish. The PHP endpoint now reads and writes objects as objects, like the Python server, and the page editor repairs pages already stored this way when it opens them.
- **Stats tab names hidden datasets on PHP hosts**: the Stats table on a PHP host now shows the display name of a hidden or not-yet-configured dataset that has views or downloads, instead of its raw `<type>/<folder>` id. It takes names from every published dataset, as the Python server already did, rather than from the filtered public catalog.
- **Timelapse exports and lossless reads stay on one frame**: the OME-Zarr export reads every shard from the frame it was planned on, and stops with a clear message if the timeline moves mid-export instead of writing a zip that combines several frames and fills the rest with zeros. The Q30 bricks download takes its index, manifest, `metadata.json` and every pack from the timepoint on screen when it started, instead of storing another frame's packs under the first frame's index (a corrupt zip). `DataAccess.readRegion` (used by Graphs and measurements) ties its read to the tree it planned on and fails when a timepoint was mounted in between, instead of returning another frame's voxels.
- **A failed OME-Zarr export stops completely**: when one shard cannot be read, the shard the other runner is still encoding is discarded instead of being written and shown as progress. In browsers without a save picker, the in-memory file takes nothing more once the export is aborted, so no stray download or memory growth follows the "Export failed" message.
- **Studio figures of a timelapse stay on their own frame**: opening the Studio pauses playback, and the native pass (and the lossless export pass of a format-6 tree) runs on the frame the figure was opened on, loading it again first if another frame is on screen. If the frame changes while the pass runs, the pass stops with a message, so a figure no longer mixes two timepoints or gets relabelled with another frame.
- **Lossless exports never fall back to the lossy volume silently**: if the lossless reload is interrupted or the GPU settles on a coarser level, the export stops with a clear message instead of rendering from what is on screen. A playing timelapse is paused first.
- **Decompose export uses one timepoint**: on a playing timelapse the figure waits for the displayed frame and holds playback, so the main view and the channel vignettes show the same timepoint. Export failures now appear as a readable message.
- **Studio retries planes and layer MIPs after a network hiccup**: one failed request for `planes/` or `mips/` no longer sends every later native cut to the much heavier brick path until the page is reloaded. Only a missing or invalid tree is remembered.
- **Native XZ/YZ Studio cuts reject a mismatched cut pack**: the lossless XZ/YZ reader checks the pack's tile grid and the size of every decoded tile against the level. A corrupt pack, or one from another level or tree, falls back to the bricks path instead of handing the Studio a scrambled "native" figure.
- **A cancelled load no longer breaks another one**: the index of a format 5/6 quality column, a plane pack's header, an XZ/YZ pack head and a cut index are fetched once under no caller's cancellation, and each caller stops waiting on its own, so cancelling a timepoint prefetch or a Studio pass no longer makes the load sharing the fetch fail with an abort error. A brick batch cancelled while its column index is still loading ends as a normal cancelled batch. On hosts without byte ranges, a whole pack whose first reader was cancelled leaves the cache and the next reader downloads it itself, instead of every later cut read of that pack failing.
- **A silent server no longer freezes brick streaming**: a pack or byte-range request that gets no response headers within `fetchStallMs` (30 s) is cancelled and retried, and fails as `BRICKS_FETCH_STALL` if it keeps hanging. It used to hold one of the four pack-fetch slots, and the host's first range request every other range read waits on, until the dataset was switched.
- **Timelapse prefetch keeps the next frame and stays within its budget**: packs still downloading count toward the prefetch budget at their planned size, so the t+1, t−1 and t+2 requests of one frame step share one budget in that order instead of downloading about three times the budget and discarding the excess. When room is needed, the packs of farther or older frames are dropped before the next frame's, and a pack the display needs while its prefetch is still queued moves ahead of the other background downloads.
- **Decode workers no longer leak memory when a load is cancelled**: when a brick load was superseded (timepoint scrub or playback, quality switch, Studio pass closed), each decode worker that was mid-brick created that brick's assembly buffer (about 1.1 MB) after the cancel had already cleared it, and nothing freed it until the dataset changed. A cancelled job now checks as soon as its picture is decoded and forgets its assembly, and a drop request waits until the jobs posted before it have finished.
- **No leftover memory after a failed z-stack MIP**: when one plane pack of a Studio MIP slab failed to download, the packs still in flight could re-create their band buffers in the decode workers after cleanup, and these buffers (tens of MB each) stayed for the life of the page. The slab now waits for every in-flight pack before releasing the buffers, and still reports the original error.
- **GPU compression no longer switched off for good by one context loss**: on a desktop GPU, any WebGL context loss while a volume was shown stopped that browser from ever using compressed (RGTC) GPU memory again, so every volume took about 2.4× the VRAM. A loss now counts against compression only if it comes right after a compressed allocation or is the second such loss in a week, or if the GPU refuses a compressed page outright, in which case the same level reloads uncompressed straight away. Any mark expires after a week.
- **3D view export stays under the GPU watchdog**: export tiles are sized so that one draw marches no more pixel·samples than a screen frame. Exporting a large PNG from a small canvas, such as a Compare panel, no longer risks a GPU timeout and a lost WebGL context; the image itself is unchanged.
- **Z extent of a volume matches its voxels**: the 3D box of a stack of n planes is now n × z-step deep instead of (n − 1) × z-step plus a slice thickness. On datasets without an explicit thickness, Z distances were about 1 % short, and in the far third of the stack a native-voxel lookup through `ctx.data` read the plane one below the one under the cursor.
- **Picking on a stabilised timelapse**: a point picked in the part of the display box that the series' drift adds is no longer pinned to the acquisition box face, so distances and plane placement there are right. `ctx.data.screenToVoxel` reads the voxel of the timepoint on screen through the stabilisation warp, and answers null where that timepoint holds no data instead of returning the edge voxel.
- **A stabilised timelapse frame no longer jumps into place after loading**: a frame visited for the first time was drawn through the previous frame's rigid transform while its bricks streamed, then snapped into place when the load finished, and a pick taken in that window used the wrong transform. Each frame now brings its own transform, applied the moment it appears, coarse preview included.
- **Changing quality during a frame load keeps the requested frame**: a quality change made while a timelapse frame was still loading reloaded the previous frame and silently dropped the requested one, so the scrubber and the volume disagreed, and in Compare the panel announced the old frame to its siblings. The quality switch now loads the frame the scrubber asked for, and a same-frame quality reload no longer posts a time sync.
- **Quality controls stay clickable during playback**: each timepoint load refreshed the quality list and matrix twice and rebuilt every button, so clicks and keyboard focus were lost while a timelapse played. The refresh now runs once per load and redraws only when something it shows has changed (the level on screen, the GPU budget, the download times, the choice, the language).
- **Reset workspace restores the stabilised frame**: on a stabilised timelapse switched to "Raw images", Reset workspace now returns the volume and the tracking layer to the stabilised view the dataset opens in, instead of keeping the raw frame and recording it as the untouched state.
- **Renamed channels survive a restore**: a channel name edited in the sidebar is restored from a saved workspace or a shared link instead of going back to the metadata name, so Compare goes on pairing that channel with its siblings by name; an emptied name field keeps the previous name.
- **Broken shared links still frame the volume**: a truncated or corrupt `#state=` link, a saved view without a camera, or a restore that failed no longer leaves the specimen at the default camera distance. The volume is framed as on a normal open.
- **A restored view with the sidebar hidden keeps its reopen button**: opening a shared `#state=` link or a saved workspace with the sidebar collapsed shows the floating button that brings the sidebar back, instead of leaving channels, quality and the Studio unreachable.
- **Presentation mode can be left again**: Escape or the new exit button on the canvas leaves the mode; before, the mode hid its own toolbar button with the header and nothing else turned it off. A shared link or a saved view no longer re-enters it unless the presentation-mode plugin is installed to offer the way out (presentation-mode 1.1.4).
- **Studio shortcuts no longer change the viewer's tool**: pressing V, D, C, M or Escape inside the Studio switched the page's tool underneath the overlay and closed the slice inspector the figure came from. The tool manager now ignores its shortcuts while the Studio is open.
- **Clearing measurements in the 3D viewer forgets the pending first point**: the measure-distance tool did not listen to the viewer's Clear button, so a first point picked before a clear was paired with the next click, and new measurements kept counting from the cleared list. The tool now listens to the Clear button of whichever page it runs on and numbers new measurements from the stored list (measure-distance 1.1.5).
- **Cell distance snapshots follow the stabilisation switch**: switching a timelapse between the stabilised and raw frames of reference left the snapshot measurements of the Cell Distance tool in the other frame's coordinates, so they floated away from their cells. They are now redrawn on their cells in the frame shown, and the CSV and JSON exports say which frame of reference each row's points are in (tracking-measure 1.0.3).
- **2D orientation buttons act once after a language switch**: each language switch added another click handler to the Orientation 2D panel, so a 90° rotation turned the photograph 180° and Mirror seemed to do nothing. The handler is now bound once, and the panel title follows the selected language (orientation-2d 1.0.4).
- **A photograph panel's sidebar opens again in Compare and split view**: the 2D page now drops the boot-time fold (`panel-boot`) as soon as its own `sidebar-hidden` class carries it. The settings button of a photograph pane could never show its sidebar tools (orientation, display adjustments, grid, stain isolation).
- **Graphs no longer re-read a playing timelapse**: with the Graphs panel open on a playing series, the plugin started a lossless read of a whole level at every timepoint, and none was ever cancelled. It now waits until the timepoint has stayed put for a moment before reading, and a read for a timepoint no longer on screen is aborted at once.
- **Graphs shows how much of the volume is read**: opening Graphs on a volume showed only "Computing…" while the lossless voxels downloaded, which could take tens of seconds on a slow host. The status now reads "Reading the volume… N %", fed by a new `onProgress` option of `DataAccess.readRegion` (Compare keeps the plain status).
- **Compare graphs explain a missing panel and follow the language**: a panel's own reason now reaches the Compare graphs drawer, so a dataset still loading shows "not ready yet" and a missing table shows "nothing to plot" instead of a generic failure, and a request replaced by a newer one no longer shows as an error. The drawer's data, X and Y pickers, its close button and the plotted series switch language with the page; the panels rebuild their translated tables and the drawer asks them again once they have switched.
- **A Compare panel lowers its GPU budget after a context loss**: a panel's share of the machine is now a cap on the page's own budget (`SVRManager.setVramCap`), not an override, so the halving after a WebGL context loss applies again and the reload comes back at a coarser level instead of looping on the same atlas. The budget a panel reports to the host is read fresh, without the share.
- **Compare panels keep their share of brick decodes**: a panel's share of concurrent decodes is now a cap (`BrickLoader.configure({ maxConcurrency })`) that every batch respects. Each volume load used to reset the share to the per-quality 32, so four panels decoded 4 × 32 bricks at once instead of the divided figure. A lone viewer has no cap and is unchanged.
- **Default view and calibration in the dataset editor**: saving a new calibration now updates the open preview (gizmo, sample-side switch, axis-aligned views), so a custom default view captured right afterwards is no longer stored against the old calibration and opened in the wrong pose for every visitor; choosing a default view while the orientation is being defined is refused with an explanation (orientation-axes 1.3.5). Switching the admin language mid-calibration no longer resets the button while the preview stays in calibration mode, so Save records the dragged pose instead of silently skipping it.
- **Preview capture in the dataset editor**: *Set the preview* now captures a 2D photograph on screen (the 2D page never answered, so the button spun forever). A click before the volume preview has loaded gets a "not ready" answer, a page that never answers releases the button after 8 seconds with a clear message, an answer about a dataset you have since left is ignored, and capture errors are shown as a translated sentence.
- **Admin datasets on a narrow screen no longer stream a hidden preview**: at 860 px or less, where the preview column is hidden, selecting a dataset mounts no viewer and a running one is unloaded. Defining the orientation and capturing or posing a default view are disabled with a hint, so no view is saved that the operator never saw; the sample side and the axis names stay editable, and widening the window brings the preview back.
- **Editor follows a staged dataset when it is published or discarded**: when the import open in the Datasets editor is published, the editor reopens it as the published dataset; when it is discarded, the editor closes. Save, visibility and gallery actions used to keep failing against a staging id that no longer existed. The import dock also asks before publishing or discarding an import whose unsaved edits are open in the editor.
- **Gallery uploads stay on their dataset and keep unsaved edits**: opening another dataset (or closing the editor) during a multi-image gallery upload stops the remaining uploads instead of attaching them to the newly opened dataset, a late server answer is no longer written into the other dataset's editor, and the operator is told how many images were not sent. Adding or removing a gallery image no longer resets the captions being typed and the reordering done since the last save; they stay in the editor and are still reported as unsaved.
- **Missing gallery images leave the whole gallery**: an attached image whose file is gone from the dataset folder is removed from the lightbox's navigation, its counter and the dock counts, not just from the grid, whether its thumbnail failed in the dock or it first failed in the lightbox. Closing the lightbox focuses the tile of the image that was on screen, not its neighbour.
- **An import behind a proxy body limit can finish**: when a chunk is refused as too large (for example nginx's default 1 MiB `client_max_body_size`), the smaller chunk size sticks for the session instead of being reset by the server's advertised size on the next attempt. Both servers re-plan an unfinished file at the smaller size and keep every byte already stored, so *Retry* resumes instead of hitting the same 413 forever.
- **Resuming an import after signing in again no longer fails every file with 403**: the transfer worker receives the new session token on sign-in and before a resume, and a chunk still refused for a stale token waits for the current token and is resent instead of the file being reported as failed.
- **A second folder dropped during an import no longer hides the running transfer's controls**: a drop that finds no dataset, or nothing left to send, gives the running transfer back its *uploading* state, so Pause/Stop and the leave-page guard stay active. If the first transfer finished while the second drop was being planned, the drop ends in *done* and refreshes the staged list.
- **Format 1 and 3 datasets convert in the browser on hosts with a small post_max_size**: a converted m002 or m004 unit (up to about 17 MB) larger than the host's request limit is uploaded in pieces, like m005/m006 units, instead of failing with `body_truncated`. That error now names `post_max_size` and the limit.
- **A retried last piece no longer fails a dataset update**: when the server stored a unit but its answer was lost (proxy timeout), the browser's retry of the last piece is acknowledged instead of being refused with a fatal 409. A piece still in flight after a cancel or pause no longer recreates the job's storage folder.
- **An m006 update interrupted right after its commit point finishes instead of being discarded**: Retry now completes it and Discard is refused, so `planes/` and `mips/` are re-stamped with the new manifest instead of being offered for a full rebuild.
- **A running platform update stays on screen in the Updates tab**: switching the admin language or clicking *Check* during an update no longer hides the progress card or brings back the *Update now* / *Confirm* buttons. The card is redrawn with its last progress, in the new language, through the download, the restart and the one-request apply of PHP hosts; a second apply can no longer be started by mistake, and the controls come back only when the update fails or is refused. On a Python host the line under the progress bar is built in the browser from the phase and the downloaded bytes, instead of showing the server's French log sentence in every language.
- **A mistyped re-auth password no longer signs the admin out**: a wrong current password in the Security tab, or a wrong password in the plugin approval or catalog install/update dialog, replaced the whole admin panel with the login screen and hid the "incorrect password" message behind it. The panel now stays in place and shows the refusal; only a lost session goes back to sign-in.
- **Setup wizard no longer overwrites the site theme**: re-running the first-run wizard (the password-recovery path) replaced the stored theme with the green preset on Skip or Finish. The theme is written only when a colour is clicked, and that colour is merged into the stored theme so font, corners and other Appearance settings are kept; step 3 outlines the colour the site uses now. The Back button, which did nothing on step 2 because the account of step 1 already exists, appears from step 3 onwards.
- **Legal editor Save button stays enabled after structural edits**: adding or deleting a section, or switching the editing language, greyed out *Save* while the changes were still unsaved. The button now reflects the unsaved state every time the editor is redrawn.
- **Admin messages in the admin's language, without exception text**: Data updates (automatic restarts and their history, failed updates, the speed test), the import worker, the Integrity tab (expired session, empty server answer, network error), dataset trash failures (folder in use, trash unreachable, damaged entry, entry gone…) and refused media uploads in the Pages editor (unsupported type, empty or over 8 MB, server cannot write) now say the cause in a translated sentence instead of the server's raw code, its French or English sentence, the bare id "auto_retry" or browser text such as "Failed to fetch". The server's own error text is still shown where it helps, and the technical detail goes to the browser console.
- **Integrity tab keeps focus and reports a failed list**: each dataset result used to rebuild the whole tab, which sent keyboard focus back to the page and folded any open findings; the control in use and the open rows now survive each result, and focus returns to the Run button when the check-up ends. When the server cannot return the list of datasets, the tab shows an alert telling the operator to check the server log and run the check-up again instead of falling back to its empty start state.
- **File sizes in the admin are shown in the operator's language**: the import tab, the upload dock, Docs, the dataset trash, integrity checks and page import/export share one formatter that uses the translated units and the page's number format. Some tabs showed French units (Ko, Mo) to everyone and others English units (KB, MB) to French operators, each with its own rounding.
- **Readable placeholder for a broken page widget**: in the page editor, a widget that cannot be drawn shows its type with a translated hint (unknown type, or check its settings) instead of a raw exception message or French-only text; the error itself goes to the console.
- **Studio command palette translated**: the palette's commands, its input placeholder and its accessible name follow the page language. A typed query matches the translated command name ("annuler", "exporter"), and the English name still matches.
- **Explorer stage filter label**: the first option of the stage filter read "All Types" in every language. It now reads "All Stages".
- **Public navigation works on phones**: below 900 px the public pages (home, explorer, about, custom pages, legal notices, 404) fold their links, including the operator's custom pages, into a menu opened by a button in the bar. The links used to vanish on the home page and run off-screen elsewhere, taking the language, colour-blind and theme buttons with them. The menu closes on Escape, on an outside click or on a link, and the brand name truncates so the bar fits a 375 px screen.
- **Phone layouts for the 2D page, Compare and the admin editors**: on a viewport 700 px wide or less the 2D page opens with its sidebar folded, so the 320 px sidebar no longer squeezes the photograph into a strip about 55 px wide. Below 720 px the automatic Compare layout stacks the panels in one scrolling column, each at least 60 % of the screen tall (the Columns, Rows and Grid layouts are unchanged). Below 760 px the Appearance controls and the page editor sidebar stack above the live preview and page canvas instead of squeezing them to a few pixels.
- **Readable contrast for active controls and admin text**: the selected chips of the Graphs panel, the active tool chips and the active toggles, tool buttons and type filters of the Compare page fill with the strong primary colour, so their white labels reach WCAG AA in the dark theme and under an operator's own brand colour. In the admin, error, warning and success text uses dedicated colours that reach AA on white in the light theme, and muted text (hints, metadata, group labels) rises from 2.2–2.9:1 to at least 4.5:1 in both themes, with secondary text kept brighter than muted text.
- **Borders and separators restored on Compare, the 2D page and the viewer panels**: several stylesheets and inline styles read colour tokens no theme defines (`--border-light`, `--border-color`, `--bg-card`, `--bg-panel`, `--primary`), so the Compare panel gutters, header rules, picker border and the 2D figure modal lost their borders, and the Decompose view being edited had no highlight. They now use the theme's own tokens, and a test fails on any new undefined token.
- **Viewer tools work from the keyboard**: the timelapse scrubber is a focusable slider (arrow keys, Page Up/Down for 10 frames, Home, End) that announces the frame shown, and the play button is named Play/Pause. On the Z-stack slider, Shift+↑/↓ moves the upper trim and Alt+↑/↓ the lower one, Enter or Space on the 3D notch shows every kept slice again, and the slider and trim handle tooltips describe these keys (zstack-browser 1.2.3). Studio layer rows take focus, are announced by name, select with Enter or Space and move with the arrow keys, Home and End, with focus kept on the list after each change, including Delete. Each Decompose view is a named button that opens edit mode with Enter or Space, focus moves to Done and back, and lands on Add Combination after a view is removed; the trash button of a custom view names the view it deletes.
- **2D figure builder is a proper dialog**: the figure panel builder takes focus when it opens, keeps Tab inside, closes with Escape, and gives focus back to the toolbar button when it closes or hands off to the Studio; page shortcuts no longer act on the photograph behind it (figure-panel 1.1.4).
- **Focus and states for screen readers on the public pages**: the controls of a folded sidebar (viewer, 2D page, Compare panels) are taken out of the Tab order and hidden from screen readers, so typing can no longer change channels or quality unseen. The Compare type filters, tool chips and panel settings buttons and the Explorer grid/list switch expose their state with `aria-pressed`, and the icon-only panel buttons have translated names. Closing a Compare drawer returns focus to its toolbar button, and closing a panel moves it to the next panel's close button or to Add dataset. The colour, show/hide and delete buttons of distance and cell-distance measurements, the measurement label field and the remove button of a new footer link carry a translated tooltip and screen-reader label, the show/hide label following the current state.
- **Admin keyboard and screen-reader access**: each plugin switch is announced with its plugin's name and, when locked, the reason; the dataset visibility switch and the search clear button have names, switches show a focus ring from the keyboard, and the preview and editor frames have translated titles. The collapsed sidebar rail keeps each tab's label as an accessible name and tooltip, and its button reads Expand. The mobile menu button reports whether the drawer is open, moves focus to the current tab, closes on Escape or a backdrop click and returns focus; the closed drawer leaves the Tab order. The password confirmation, the Pages export/import dialogs and the leave-during-upload warning are real modals (accessible name, focus trapped, page behind unreachable, focus returned), and the import list keeps focus on the control just changed. The Statistics columns sort from the keyboard with the order announced, and the setup wizard's colour swatches have translated names, report `aria-pressed` and sit in a labelled group.
- **Admin notifications and import progress are announced without flooding**: admin toasts are spoken through persistent polite and assertive regions, stay on screen in proportion to their length (3–8 s), pause while hovered or focused, and errors stay until closed with a new close button; at most five toasts are shown at once. The floating import dock is no longer a live region repainting bytes, speed and ETA several times a second: a separate status line announces only state changes (paused, connection lost, done, a dataset ready or failed) and every 10 % of the transfer, and the progress bar exposes its value on demand.
- **Studio native picture survives a frame still loading**: opening the Studio on a timelapse during playback, or before a scrubbed frame had loaded, aborted the native pass with 'no longer on frame N' when that load landed. The pass now loads the figure's frame over any other frame request still in flight, so that load goes stale and cannot take the screen.
- **Timeline scrubber restored when the Studio cannot reload its frame**: when the figure's frame could not be loaded again for its native picture, the scrubber stayed on that frame while another one was on screen. It now returns to the frame actually shown.
- **Exports and lossless reads use the timepoint on screen**: on a timelapse, the background prefetch mounts the frames after the one shown, and a cached frame is shown without a mount. The OME-Zarr export, the Q30 download and `ctx.data` reads (graphs, measurements) used to read whatever tree was mounted, usually a prefetched neighbour. They now pin the tree of the volume on screen (`BrickLoader.pinTree` / `withMount`, `VolumeViewer.getDisplayedTree`, `DataAccess.displayedTree` / `pinDisplayed`) and read it to the end. A prefetch or a scrub during an export no longer fails it or changes its contents; only a dataset switch stops it, and the message now says so.
- **Shared index and header reads have a deadline**: a column index, cut index, XZ/YZ pack head or plane header is shared by every reader of a tree, so it runs under no caller's signal. A server that accepted the request and never answered left it cached for good, and every later Studio pass, column switch or quality step waited on it. Each such read now has its own stall deadline (`fetchStallMs`; `CutStore.configure` / `PlaneLoader.configure` accept it too). On expiry it fails with a coded stall (BRICKS_FETCH_STALL, CUT_FETCH_STALL, PLANES_STALL), its cache entry is dropped, and the next reader fetches again. On a host without Range, the whole pack a header needs is read under the caller's signal again, so cancelling the pass stops that download.
- **Closing Graphs no longer starts a queued query**: a draw that was waiting behind a running lossless read is now cancelled when the panel closes, is relabelled or the plugin is disposed. Before, it started right after the abort and read the whole level again for a panel nobody could see.
- **First-run setup works on PHP hosts that disable link()**: the credential setup called link() unguarded; on PHP 8 a function in disable_functions is undefined and throws, so setup answered 500 and left a temp file on every retry. It now uses the hard link only when available and otherwise the create-exclusive write, always removing its temp file.
- **PHP metadata-identity stamp ignored by git**: api/.metadata-identity.sig, written by the PHP backend after a clean metadata pass, is now listed with the other PHP runtime stores in .gitignore so a checkout served by php -S does not show it as an untracked file.
- **A migration run no longer credits a discarded job's units to the next one**: the server executor journals stored units in batches, and a run still going after Discard + Update again could mark units whose tiles the cancel had deleted (stage-A planes then read as zeros). Each job's journal now carries a random `jobId` (both backends), and a batch is credited only to the job it was computed for; a run that outlives its job stops with `no_job`.
- **2D admin preview keeps its sidebar**: the phone-width sidebar fold of the photograph page no longer fires in headless mode (the admin Datasets preview, often under 700 px wide on a laptop), where the header and its hamburger are hidden and the sidebar could not be reopened; Compare panes keep their own fold.
- **Studio native picture reads the frame it is labelled with**: when the Studio's frame of a timelapse was put back from the cache while another frame was still streaming, the native pass could read that other frame's bricks under the figure's frame number, or the other frame could take the screen. The pass now mounts the brick tree on screen, keeps the background prefetch off while it runs, and names that tree to every batch, so a tree mounted anyway fails the batch instead of being read.
- **A cached frame stops the frame stream it replaces**: a display load served from the cache now supersedes a frame stream still in its manifest fetch, mount or coarse preview, which could otherwise replace the frame just put back. A prefetch cancelled that early now stops before mounting its tree. Playback through cached frames still leaves the prefetch of the frames ahead running.
- **Graphs follow the timelapse frame on screen**: the voxel table of the Graphs panel is now rebuilt when the frame on screen changes and not when the background prefetch mounts later timepoints, so scrubbing to a cached frame updates the graph and the prefetch no longer re-reads the whole lossless level.
- **Graphs: restoring a workspace with the panel closed reads nothing**: restoring a workspace saved with Graphs closed (Download Center *Restore state*, a Compare workspace) used to draw anyway. On a 3D page that meant reading a whole lossless level for a panel nobody sees and keeping it in memory; in Compare it meant asking every panel to compute. The saved choices are now only stored, and reopening draws them, even on a panel that had never been opened.
- **Studio figures name the frame on screen**: on a timelapse's first visit to a frame, the frame's coarse level is shown before its load finishes, but the Studio preview was labelled with the previous frame. Its native pass then put that previous frame back on screen and filled switched-off channels and missing chunks from the other frame's preview, making a mixed-frame figure. The preview (and the Compare Studio capture) now carries the frame of the displayed volume (`VolumeViewer.getDisplayedTimepoint`, `getDisplayedTree().timepoint`), and the native pass waits for that frame's own load instead of starting it over. A pass whose displayed frame is not the figure's keeps the preview with the frame notice.
- **Graphs and lossless reads no longer fall back to a prefetched frame**: when the viewer shows no brick tree (its volumes released by a WebGL context loss, or nothing activated yet), `DataAccess.displayedTree()` now answers `{path: null}` instead of BrickLoader's mounted tree, which on a timelapse is the last frame the background prefetch loaded. `readRegion`/`valueAt` are refused `NO_DATASET`. The Graphs voxel table keeps its last table and neither marks it stale nor re-reads, so a GPU reset no longer replots another frame's values under frame 0's timeline. A table refused NOT_READY redraws once a frame is back on screen. The Q30 bricks download is no longer offered while no frame is on screen, so it cannot package the prefetched frame.
- **Graphs choices restored onto a closed panel survive the next save**: a workspace or `#state=` link restored with Graphs closed parks its choices until the panel first describes its tables. `getState()` now returns those parked choices, so the 1 s URL sync, *Save state* and the brick-tree handoff keep the restored table, spec, colouring and preset instead of writing the defaults.
- **Studio native picture never read from a frame that is not on screen**: with nothing displayed (the WebGL context lost, or restored without its volume), the native/lossless pass of a timelapse figure fell back to the scrubber's frame and the mounted tree, which the prefetch may have moved to a later frame, so an exported PNG could mix two frames under one label. The pass now first puts the figure's frame back on screen, or keeps the preview with a notice. It stops if the volume leaves the screen, and reads cut stores from the mounted tree's own path.
- **Opening the Studio no longer reloads the frame already on screen**: when another timelapse frame was loading hidden behind the figure's frame, the native pass re-streamed the frame on screen. For a native or degraded frame that meant a full re-download next to its own resident copy, which could also lower the quality. That other load is now dropped instead (new `VolumeViewer.cancelDisplayLoad`), and a later context-loss replay still reloads the frame on screen.
- **The Q30 download appears once the frame is back on screen**: opening the Download Center while the viewer showed no brick tree (a timepoint's coarse preview still loading, or a WebGL context loss) hid the 'Display bricks (WebP Q30)' section until the Download Center was reopened, because the section only kept looking while the brick loader was not mounted; it now keeps looking until a tree is on screen and appears as soon as that tree has the Q30 column.
- **The scrubber follows a scrub made after closing the Studio**: when a Studio figure's frame was being streamed again and the operator closed the Studio and dragged the timeline, the superseded reload put the scrubber back on the previous frame while the new frame landed on screen; the scrubber is now reset only when the reload really failed and no later frame request or load took over.
- **Opening the Studio holds the timelapse on the figure's frame**: a load of another frame streaming behind the one on screen (and any frame queued behind it) is now dropped when the Studio opens, on every format. Before, on format 6 (no pass at open) it landed under the figure, and the lossless PNG export then streamed the figure's whole native frame a second time, possibly at a coarser level. A dropped load is also no longer the target a quality switch reloads.
- **PHP safety-net test runs on the CI build of PHP 8.1**: deb.sury.org's PHP 8.1.34 ends an out-of-memory fatal without running shutdown functions, which killed the test's built-in server and failed every later check. Each memory-fatal case now runs on its own server, falls back to the CLI with the net forced on, and on such a build checks only that nothing leaks; official builds still prove the HTTP 500 answer.
- **CI installs tifffile**: the download-bundle TIFF calibration test needs `tifffile` (an optional pipeline dependency) and printed SKIP on the runner, which `--strict-skips` turns into a failure; the CI and release workflows now install `tifffile==2026.9.20` beside the other pipeline packages.

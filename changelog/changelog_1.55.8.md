# Changelog v1.55.8 (Web Platform)

## [FIXED]

- **Switching the sample side tumbled the model diagonally**: turning the sample over was a half-turn about the volume's *own* X axis, which is only horizontal on screen while the file axes sit on the world axes — on a calibrated dataset the frame has tilted them, so the switch looked like a 90° diagonal tumble instead of a flip. The turn-over is now a half-turn about the **screen's vertical axis** (world Y, applied in world space): left and right swap, up stays up, whatever the pose — the same half-turn `setView`'s back side uses. The raw pose of an upside-down file is that same half-turn (`getRawPoseQuaternion(flag)`), so the z-stack browser's top face and the raw view agree.
- **The switch no longer rewrites the calibration**: `metadata.orientation` (Q_base) maps file axes to anatomy — a fact of the file that does not depend on which side is looked at — so it must not change with the side; v1.55.7 turned it over with the volume, which silently moved the anatomical labels onto other file directions. The gizmo (Q_cube · Q_base⁻¹) turns with the volume by itself. What does change is the **default view**, a pose of the anatomy on screen: the orientation plugin turns it to the opposite side and hands it back (`SAMPLE_SIDE_RESULT.defaultView`), the editor stores it, and a named preset becomes its opposite exactly — ventral ↔ dorsal, left ↔ right, anterior ↔ posterior (a half-turn about the vertical negates the face and keeps the up direction). `orientation-axes` 1.3.1.

Tests: `tests/js/test_view_frame_spin.mjs` §8/§12 (raw pose and turn-over about the vertical, calibration untouched, screen-up kept), `tests/js/test_sample_side.mjs` (every preset maps to its opposite and yields exactly that preset's pose, custom views turn and turn back, the editor stores the default view and not the calibration).

# Changelog v1.51.0 (Plateforme Web)

## [ADDED]
* **Un seul vocabulaire pour les types de données : `3d`, `2d`, `live`, `tracking`.** Ces quatre mots sont désormais *simultanément* le dossier sous `DATA_WEB/` et sous `uploads/staging/`, le premier segment de l'identifiant d'un dataset, le champ `"type"` du `metadata.json`, ce que déclare `plugin.json#dataTypes`, le `<type>` de `staging:<type>/<folder>` et du journal d'import `uploads/state/<type>__<folder>.json`, la valeur du filtre `?type=` et le suffixe des classes CSS `badge-<type>` / `type-card--<type>`. Il n'existe plus qu'une orthographe par type, et elle est la même partout ; les mots `fixed` et `wholemount` ont disparu du code — aucun alias, aucune double lecture, aucune couche de compatibilité. `dataset.id` et `dataset.path` valent tous les deux `'<type>/<folder>'` (les deux champs restent exposés, des appelants utilisent l'un ou l'autre), y compris le `"id"` écrit dans `metadata.json`.

* **Onglet d'administration « Types de données ».** Un nom de type n'est plus une constante du code : chaque catégorie a un *nom court* (pastilles, filtres, listes) et un *titre* (grandes cartes de l'accueil), tous deux multilingues comme la terminologie de l'onglet Identité — une chaîne plate ou un objet `{en,fr,es,nl}`. Les valeurs vont dans le bloc `datasetTypes` de `config/instance.json` via `/api/site.php` (`js/pages/admin/tab-dataset-types.js`, jumeaux Python et PHP inchangés côté écriture). Un champ **vide** signifie « non personnalisé » et laisse gagner la traduction livrée : *Réinitialiser* efface le bloc au lieu d'y figer les libellés courants. L'onglet ne touche qu'à l'affichage — ni les dossiers, ni les identifiants, ni les URL, ni quoi que ce soit sur le disque.

* **Namespace de traduction `types.*`.** `types.<3d|2d|live|tracking>.{label,title,desc}` dans `lang/{en,fr,es,nl}.json` fournit le nom par défaut, traduit, de chaque type. Il remplace les clés éparpillées `explorer.fixed` / `explorer.live` / `explorer.tracking` / `explorer.wholemount`, `landing.{fixed,live,tracking,wholemount}{Title,Desc}` et `admin.filterFixed` / `admin.filterLive`, toutes supprimées : un consommateur passe désormais par `Utils.datasetTypeLabel()` / `datasetTypeTitle()` ou par `I18n.t('types.<id>.desc')`. L'ancien namespace de page `wholemount.*` s'appelle `"2d".*`.

* **Quatre nouveaux jetons d'interpolation : `{type3d}`, `{type2d}`, `{typeLive}`, `{typeTracking}`.** Exposés par `InstanceConfig.tokens()` comme `{brand}` ou `{specimen}`, ils sont donc utilisables dans les textes de l'éditeur de pages et dans les traductions. Ils portent le nom choisi par l'administrateur, pas l'identifiant technique.

* **`I18n.raw(key)` — résolution d'une clé *sans* interpolation de jetons.** Nécessaire, pas cosmétique : `I18n.t()` interpole `{type3d}`… en passant par `InstanceConfig.tokens()`, qui résout ces jetons par `Utils.datasetTypeLabel()`, qui retombe sur la traduction par défaut du type. Avec `t()`, la toute première chaîne traduite de la page ré-entrait indéfiniment dans `t()`. Le résolveur de noms de types lit donc `I18n.raw('types.<id>.<champ>')`, ce qui coupe le cycle à la source plutôt que de l'amortir par un drapeau de ré-entrance.

* **Migration ponctuelle et idempotente d'une installation existante.** Un hôte installé avant la 1.51.0 a ses octets sous `DATA_WEB/fixed/` et `DATA_WEB/wholemount/`, ses journaux d'import sous `uploads/state/fixed__*.json` et un `api/stats.json` indexé sur `fixed/<dossier>`. Les deux backends appliquent la même conversion au démarrage : renommage de `DATA_WEB/fixed`→`3d` et `DATA_WEB/wholemount`→`2d` (et de même sous `uploads/staging/`) — enfant par enfant si la cible existe déjà, les collisions de nom étant sautées et journalisées, la source supprimée si elle devient vide ; renommage des journaux d'import et réécriture de leur champ `type` ; réécriture de `"type"` et `"id"` dans chaque `metadata.json`, ainsi que des identifiants hérités dans `linkedTrackingId` / `relatedIds` ; réindexation de `api/stats.json` (compteurs numériques additionnés en cas de collision de clé) ; renommage de `pageTitles.wholemount` ; réécriture des `explorer.html?type=fixed|wholemount` dans les `config/pages/*.json`. Les renommages passent par un `rename()` atomique protégé, pour que deux requêtes concurrentes ne s'entretuent pas. La garde d'entrée coûte quelques tests de dossier : une installation neuve ne paie rien et il n'y a aucun fichier témoin à gérer. C'est une migration, pas une couche de compatibilité — après elle, plus rien ne lit les anciens mots.

## [OPTIMIZED]
* **Une seule source côté client pour tout ce qui dépend du type.** `js/core/utils.js` — chargé sur toutes les pages et réexporté par `js/pages/admin/shared.js` — expose `DATASET_TYPES`, `VOLUME_DATASET_TYPES`, `isDatasetType`, `datasetTypeOfId`, `datasetTypeLabel`, `datasetTypeTitle`, `datasetTypeIcon`, `datasetTypeBadgeClass`, `datasetTypeGradient`, `datasetPage` (accepte un dataset ou un type nu) et `datasetUrl`. Plus aucun libellé ni aucune table icône/dégradé/page n'est écrit en dur ailleurs. `datasetTypeLabel` résout dans l'ordre : le nom de l'administrateur, la traduction `types.<id>`, puis l'identifiant lui-même — une page qui n'a chargé ni `InstanceConfig` ni `I18n` affiche donc un nom plutôt qu'une pastille vide.

* **Fichiers renommés pour coller au vocabulaire.** `wholemount.html` → `2d.html`, `js/pages/wholemount.js` → `js/pages/2d.js` (global `WholemountApp` → `App2D`), `js/viewers/wholemount-viewer.js` → `js/viewers/2d-viewer.js` (global `WholemountViewer` → `Viewer2D`), `css/wholemount.css` → `css/2d.css`, `preprocess/wholemount_importer.py` → `preprocess/2d_importer.py`. Les liens internes suivent ; la plateforme tourne sur un site unique et aucun lien externe n'avait été partagé.

* **Classes CSS préfixées par construction.** `.3d` et `.2d` ne sont pas des sélecteurs valides — un identifiant CSS ne peut pas commencer par un chiffre. Les classes dérivées d'un type passent donc toutes par un préfixe (`badge-<type>`, `type-card--<type>`), généré par `Utils.datasetTypeBadgeClass()` au lieu d'être interpolé à la main ; une règle qui ne s'applique jamais n'émet aucune erreur, c'est exactement le genre de panne qu'on ne voit pas.

## [FIXED]
* **Les filtres de l'onglet Datasets ne couvraient que deux types sur quatre.** La barre était écrite en dur (`Tous` / `Fixed` / `Live` / `Masqués` / `Import`) : un dataset `tracking` ou une photographie n'étaient atteignables que par `Tous`, alors que le filtrage les aurait acceptés. Les pastilles de type sont maintenant engendrées depuis la liste canonique, avec les noms choisis par l'administrateur, puis suivies des pseudo-filtres *Masqués* et *Import*.

* **L'aperçu d'un dataset `tracking` ouvrait le visualiseur 3D.** L'onglet Datasets réimplémentait la table « type → page » et avait oublié la branche `tracking`. Il appelle désormais `Utils.datasetPage()`, le seul endroit qui connaît cette correspondance.

* **Une photographie avait un identifiant nu là où un volume avait `type/dossier`.** L'importeur 2D écrivait `"id": "<dossier>"` dans `metadata.json` quand `4-catalog_generator.py` écrivait `"id": "fixed/<dossier>"` : deux formes d'identifiant coexistaient sur le disque. Les deux écrivent maintenant `'<type>/<dossier>'`.

* **`Même [object Object]/stade` dans les relations entre datasets.** `catalog.js` lisait `specimen.singular` par un `InstanceConfig.get()` brut, alors que la valeur stockée est localisable : une instance qui l'avait renseignée par langue voyait l'objet rendu tel quel dans le libellé. La lecture passe par `InstanceConfig.localized()`, désormais exposé.

* **Un dataset encore en cours de préparation n'avait pas de champ `path`.** La branche « le dossier existe mais son `metadata.json` n'est pas encore là » de la liste des datasets n'émettait que l'identifiant. Tant que `id` et `path` étaient la même chaîne le manque était invisible ; il émet maintenant les deux.

* **Le bloc `:run_2d` du lanceur de la chaîne de traitement était dupliqué.** `tools/pipeline_bundle/RUN.bat.in` contenait deux copies identiques du même label ; `cmd.exe` utilise silencieusement la première, et tout patch textuel sur ce fichier en aurait créé une troisième. Le doublon est supprimé.

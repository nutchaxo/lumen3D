# Changelog v1.47.0 (Plateforme Web)

## [ADDED]
* **Un quatrième type de dataset : `wholemount`.** Une photographie couleur d'embryon entier prise au stéréomicroscope (export TIFF depuis un `.lif` Leica) est désormais un dataset à part entière, rangé sous `DATA_WEB/wholemount/<nom>/`. Un dataset = une image : `image.webp` (résolution native), `preview.webp` (640 px), `thumbnail.webp`, `metadata.json` (stade, lignée, coloration, taille de pixel, réglages d'acquisition), et en option `download/` avec le TIFF d'origine. Aucune brique, aucun canal : le type est reconnu partout où la plateforme énumère ses types — catalogue Python et PHP, éditeur de datasets, import navigateur (allowlist fermée étendue à `preview.webp` / `image.webp`, refusés pour tout autre type ; `bricks/` refusé pour un wholemount), centre de téléchargement, statistiques, installateur.

* **Page `wholemount.html` — visualiseur 2D calibré.** Canvas pan/zoom (molette, glisser, pincement, double-clic pour ajuster), barre d'échelle 1-2-5 exacte calculée depuis `pixelSizeUm`, mesures de distance en µm par clic (même contrat `{normalized, physicalUm}` que le viewer 3D, persistées par dataset), bascule **« Isoler le marquage »** qui affiche le spécimen en gris atténué et le marquage en cyan : rapport `B/R` (le X-gal abaisse R et G, pas B ; mesuré entre 2 et 4 dans les cœurs les plus denses) gardé par un contexte tissulaire (moyenne locale de la « jaunisseté » sur ≈ 40 px) qui éteint les paillettes bleues du fond, ajustement / 1:1, panneau spécimen (stade, lignée, coloration, date de dissection, zoom, taille de pixel, champ, microscope, caméra, exposition, gain, fichier source), galerie et datasets liés.

* **Planche-contact de la collection.** Depuis n'importe quel wholemount, le bouton *Parcourir* (ou `B`) affiche toutes les photographies du catalogue en grille, filtrables par stade et par lignée, avec recherche texte. Un clic ouvre la photographie **en place, sans rechargement** ; `←` / `→` passent à la précédente / suivante dans l'ordre filtré, l'URL suit (`history.pushState`, le bouton Précédent du navigateur fonctionne). L'affichage est quasi instantané : l'aperçu (≈ 14 Ko) est peint dès qu'il est décodé — il vient du cache de la planche — et l'image native (≈ 200 Ko) le remplace dès réception ; les voisines sont préchargées.

* **Plugins en opt-in par type de données.** `PluginRegistry.loadModules(base, paths, { dataType })` ne charge, quand une page précise son type, que les plugins dont le `plugin.json` le déclare dans `dataTypes`. Un plugin muet reste écarté de cette page (simple information console, pas de quarantaine). `viewer.js` ne passe aucun type : le viewer 3D est strictement inchangé. Mis à jour pour le wholemount : `screenshot`, `presentation-mode`, `download-center` (utilise `ctx.ui.getCanvas` si la page le fournit), `measure-distance`.

* **Explorateur, accueil, admin.** Filtre de type *Wholemount*, badge et couleur dédiés (`--badge-wm-*`), quatrième carte de type sur l'accueil (et dans le modèle de page d'accueil de l'éditeur), compteur par type, lien vers la bonne page via `Utils.datasetPage()` — le seul endroit qui associe un type à sa page (explorateur, accueil, comparaison, tracking et widget « derniers datasets » l'utilisent). Le bouton *Comparer* n'est plus proposé pour une photographie. L'éditeur de datasets accepte un wholemount (validation sur le bloc `image`, plus de canaux exigés).

## [FIXED]
* **Le plugin `measure-distance` doublait l'unité.** La liste et les tuiles de résultat affichaient « 2.262 mm µm » : `_fmtUm` choisit déjà mm ou µm selon la grandeur, le suffixe ajouté après coup est retiré (visible aussi dans le viewer 3D).

* **`tools/build_download_bundles.py` n'est plus le seul à écrire `download/`.** L'importeur wholemount place lui-même l'original et un `README.txt` de provenance, si bien qu'un wholemount a un centre de téléchargement complet sans passer par l'outil de bundles réservé aux volumes.

## [OPTIMIZED]
* **Vérification des copies d'affichage à l'import.** `preview.webp` et `image.webp` sont vérifiés par leurs octets magiques à la finalisation (`preview_not_image` / `image_not_image`), comme la vignette ; la publication exige leur présence (`missing_preview` / `missing_image`) là où un volume exige son `bricks/manifest.json`. Un wholemount devient *éditable* dès que métadonnées, vignette et aperçu sont arrivés. Tests : `tests/test_upload_staging.py` (`TestWholemount`), `tests/test_upload_php.php`, `tests/test_dev_server_paths.py`.

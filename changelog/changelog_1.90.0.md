## [ADDED]
- **Advanced Studio 1.5.0, macros read and write the files of your computer**: a macro now reaches files through folders you grant. It never touches the server's files, the site's datasets or the network. Paths look like `/<Folder>/sub/file.tif` and can never leave a granted folder (`..` stops at the folder). A hard-coded path such as `C:\Users\me\data\` can be mapped once to a granted folder (an alias), so lab macros run unchanged.
- **File functions of ImageJ 1.54p**: `open` (TIFF, PNG, JPEG, ZIP of a TIFF, ROI and ROI sets, text, tables, LUTs), `save`, `saveAs` (Tiff, PNG, Jpeg, ZIP, Raw, Results, Text, Selection, XY Coordinates, LUT, Measurements), `getDirectory` / `getDir` (including `home`, `temp`, `image`, `file`), `getFileList`, every `File.*` function (`open` / `print` / `close` writers, `append`, `saveString`, `openAsString`, `copy`, `rename`, `delete`, `makeDirectory`, `exists`, `length`, `lastModified`, `name`, `directory`…), `runMacro(file)`, `Table.open` / `Table.save`, `roiManager("open" / "save")` and `IJ.checksum`. File commands reached through `run()` (Open..., Tiff..., PNG..., Jpeg..., Results..., Text File..., XY Coordinates..., Raw..., LUT...) take ImageJ's keys. A corpus of 145 file macros was run in the real `ij-1.54p.jar` and the Studio gives the same Log, files and pixels. The cases that differ are documented in the test with their reason.
- **Files section in the Macro Editor**: *Add folder…* grants a folder, and each folder gets a mode: *Read-only*, *Ask* (default) or *Allow*. Under *Ask*, the first replace, delete or rename of an existing file in a run pauses with *Allow for this run* / *Refuse* / *Abort*, and the focus starts on *Refuse*. Before a run the editor counts the folder and file pickers the macro will ask for, and a picker only opens on a click. Cancelling a picker stops the macro, as in ImageJ. `/tmp/` is a browser workspace that lasts while the Studio is open. *Open…* and *Save…* buttons load and save `.ijm` files.
- **Firefox and Safari get the same macros**: these browsers cannot write into a folder of the computer, so a granted folder is read as it is and every write goes to a browser workspace laid over it. *Download results* then gives one link per file (three changed files or fewer), or a ZIP that unzips into the same folder tree, with a `README.txt` that lists deletions and renames. The ZIP is written as a stream and switches to ZIP64 past 4 GiB or 65 535 entries. The Files section, and the About box, warn that Safari may delete that workspace after 7 days without a visit.

## [CHANGED]
- **File functions no longer stop a macro with "comes in a later version"**: what stays refused has its own message: network paths and URLs, Bio-Formats, File › Import › Image Sequence, writing GIF, AVI, BMP, PGM or FITS, `.jar` files, and DICOM, FITS, PGM or AVI reading.
- **A Studio command never opens a file picker from inside a macro**: inside a run, files go through the macro's folders, and outside a run File › Open and File › Save As work as before.
- **A macro's text windows count as windows**: a text window `open()` made is seen by `isOpen`, `getList("window.titles")` and `close()`, and the Log or a text window in front answers `run("Text...")`.

## [FIXED]
- **Results columns with decimals print every cell with the precision**: once a Results or table column holds a non-integer, every cell, including an empty one (`0.000`), prints with the chosen decimals, as ImageJ's ResultsTable does. This applies to `getResultString`, `Table.getString`, the files a macro writes, and the Results and Summary windows with their Save As and Copy (a circularity of 1 in a column that already holds 0.686 now reads `1.000`, as in ImageJ).
- **`print(f, …)` writes to the file `File.open` returned**: it used to discard the text. `IJ.redirectErrorMessages()` now takes effect.
- **Safe reads**: a 16-bit PNG or a ZIP that would inflate past its declared size is stopped before memory is reserved, and a file that would not fit in the Studio's free memory is refused before a byte is read.
- **A write cut short leaves the original intact**: when the browser workspace runs out of room during a write, the partial copy is removed and the folder's own file shows again, so *Download results* cannot ship a truncated file.
- **Files section arrow**: the arrow in front of *Files* showed as "BE" / "B8" because of a broken character escape.

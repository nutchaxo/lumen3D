## [ADDED]
- **Visible time range of a timelapse (admin › Datasets)**: a new *Visible time range* section in the dataset editor, shown for timelapses only. A track represents the whole acquisition, the visible window is lit between two handles. Drag a handle, press on the track to move the nearer one, use the arrow / Page / Home / End keys on a focused handle, or type the first and last frame. The preview shows the frame under the handle you are moving, so you see what a visitor will land on. *Show the whole series* clears the window.
- **The viewer only offers that window**: a visitor's timeline runs from the first to the last visible frame. The track, scrubbing, keys, playback loop, prefetch, buffer bar and the `Buffer n/total` counter all work inside the window, and a shared link, saved workspace or Compare sync that names a frame outside it lands on the nearest visible frame. Frame numbers stay the real ones of the acquisition (frame 40 is frame 40 whatever the window), so tracking, the Studio and links keep meaning the same thing. The admin preview always shows the whole series, because that is where the window is chosen.
- **Compare aligns windows by elapsed fraction**: two panels with different windows (or lengths) follow each other by the fraction of the timeline each one shows.
- **Downloads keep the whole timeline**: the window is a view over the timeline, stored as `timeRange: { start, end }` (0-based, inclusive) in `metadata.json`. The bricks, `dimensions.t`, the `download/` folder and every export (OME-Zarr, Q30, Download Center) are untouched. A malformed or out-of-range value is ignored and the whole series is shown, so a bad value never hides a dataset. The one exception is the single frame the download TIFF and MIPs show: it is now the first visible frame (see the pipeline 0.23.2 notes).

## [CHANGED]
- **Timeline is much larger**: the bar goes from 80 to 120 px, the track from 24 to 48 px, the handle is twice as wide and taller, the play button is a 52 px round button and the frame counter is set in a larger monospace with a fixed width, so it no longer shifts as the digits change. Short windows (Compare panels, laptops under 720 px high) get a compact version, 88 px.
- **The window survives a re-import**: `timeRange` is a curated key in the pipeline (`run_preprocess.py`), the browser import (`upload_staging.py`) and its PHP twin (`api/_upload_lib.php`), so reprocessing or republishing a dataset keeps what the operator set.

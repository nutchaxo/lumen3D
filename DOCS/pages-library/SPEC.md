# Pages import / export tab + page version history — SPEC

Status: normative for web 1.87.0. Everything below is a contract between the Python backend,
its PHP twin and the admin UI. Anything not said here follows the existing conventions of
`api/site.php` / `dev_server.py` (twins, atomic writes, locks, CSRF, no-store).

## 0. What the operator asked for (verbatim intent)

* A **new admin tab** to import / export the pages (they are JSON documents under `config/pages/`).
* On import: organise / **overwrite** when a page with the same name already exists.
* Export file name: `<site>_<page name>_<date>.json` — e.g. `bemine.be_about_1911261445.json`
  (site = host name, date = `ddMMyyHHmm` in LOCAL time: 19 Nov 2026 14:45 → `1911261445`).
* On import, a **verifier**: everything is checked before any write, including that the file is
  **compatible with this site's version** — a page made by a newer platform than this one can
  support is refused.
* Several **versions of the same page** can be kept (a history). Per page, a drop-down lists its
  versions; the operator can **activate** one or another, **rename**, **export**, **delete**,
  **modify** (edit), etc.

## 1. Vocabulary

* **page** = a slug (`^[a-z0-9][a-z0-9_-]{0,63}$`): `home`, `about` (built-in) or a custom page of
  `instance.nav.customPages`.
* **live state** of a page = what `api/site.php?action=get&doc=pages/<slug>` returns to the admin:
  `{title, published, draft?, schemaVersion}`.
* **version** = an immutable-by-default snapshot of a page's content:
  `content = { title?: {loc:str}, nav?: {label:{loc:str}, show:bool}, published?: block, draft?: block }`
  with at least one of `published` / `draft`. `block` = `{sections:[…], background?}` (or the legacy
  `{blocks:[…]}`) exactly as `pages-transfer.js` `contentBlock` keeps it.
* **active version** of a page = the version the operator last *activated in publish mode*
  (marker stored with the history). The live page can drift from it afterwards (editor edits);
  the UI says "modified since" when the live state no longer equals the active version.
* **origin** of a version: `import` (came from a file), `capture` (operator saved the live state),
  `auto` (safety snapshot taken by the server before an activation / overwrite replaces the live
  state), `manual` (created by hand, e.g. duplicate).

## 2. Storage (server)

`api/page-versions/<slug>.json`, mode 0600, **never web-served** (the whole `api/` tree is denied;
`api/page-versions` is added to `_UPDATE_PROTECT`, `api/_admin_lib.php` protect lists,
`install.php` protect list, and `tools/build_release.py:API_RUNTIME_DIRS`).
The history survives deleting the page (it is how a deleted page is restored).
The file format is identical for both backends (a host can switch backend):

```json
{
  "schema": "lumen-page-versions/1",
  "slug": "about",
  "active": "v0a1b2c3d4e5" ,
  "versions": [
    {
      "id": "v0a1b2c3d4e5",
      "label": "Spring redesign",
      "note": "",
      "origin": "import",
      "createdAt": "2026-11-19T13:45:07Z",
      "updatedAt": "2026-11-19T13:45:07Z",
      "exportedAt": "2026-11-18T09:00:00.000Z",
      "source": "bemine.be",
      "platform": "1.86.0",
      "content": { "title": {}, "nav": {}, "published": {}, "draft": {} }
    }
  ]
}
```

* `versions` is stored oldest → newest; `list` answers newest first.
* `id` = `v` + 12 lowercase hex chars from a CSPRNG (`^v[0-9a-f]{12}$`), generated by the server.
* `createdAt`/`updatedAt` = server clock, UTC, `YYYY-MM-DDTHH:MM:SSZ`. `exportedAt`, `source`,
  `platform` are client-supplied informational strings (≤ 64 chars each, control characters stripped).
* Limits: **≤ 50 versions per page**, a stored file **≤ 32 MiB**, one version's blocks together
  **≤ 4 MiB** (each block ≤ 2 MiB like a page doc, measured both as UTF-8 and as the server's JSON
  encoder writes it: non-ASCII as `\uXXXX`, a `/` counted once on both backends), a block nests **≤ 64
  containers** deep (`invalid_content`; walked without recursion), a localized value ≤ 64 locales of
  ≤ 4000 characters, `label` ≤ 120 chars (trimmed; empty → `Version`), `note` ≤ 2000 chars. `active`
  is `null` when none.
* Written atomically (same helpers as the drafts: `_atomic_write` / `lumen_write_file_atomic`),
  under a per-slug lock. Lock order when both are needed: the **site doc lock first**
  (`_SITE_LOCK` / `site_locked`), then the history lock. Never the other way round.
* Every block passes the page-doc structural gate (`_validate_page_doc` / `site_validate_page`,
  applied to a probe `{published, draft}`) before it is stored; a violation → 400 `invalid_content`.
* PHP: decode with `lumen_json_decode_doc` and write with `site_doc_json`-style encoding so an empty
  object stays `{}` (never `[]`), exactly as the draft files do.

## 3. HTTP API — `api/page-versions.php` (PHP) / `/api/page-versions.php` (Python)

Admin session required for everything (anonymous → 401 `{"error":"Not authenticated"}`),
`Cache-Control: no-store` on reads. Writes = POST + CSRF (`admin_require_write()` /
`_authorize_write`); register the write actions in `_WRITE_ACTIONS`
(`add, update, activate, delete, purge`). PHP entry point requires `_bootstrap.php` (guarded by
`is_file`) and calls `session_write_close()` right after reading the session (CLAUDE.md §7).
Query parameter `slug` is validated with the slug regex (400 `invalid_slug`), `id` with the id regex
(400 `invalid_id`). Unknown action → 400 `Unknown action`.

| Action | Method | Query | Body | Answer |
|---|---|---|---|---|
| `list` | GET | `[slug=S]` | — | `{schema, limits:{maxVersions:50,maxBytes:33554432}, pages:{S:{active,count,versions:[META…newest first]}}}` — all pages that have a history, or just `S` (`pages:{}` when none) |
| `get` | GET | `slug, id` | — | `{ok:true, version:{…META, content}}` · 404 `not_found` |
| `add` | POST | `slug` | `{label?, note?, origin, content, exportedAt?, source?, platform?, activate?:"publish"|"draft", snapshotLabel?}` | `{ok:true, id, version:META, snapshotId?:string}` |
| `update` | POST | `slug, id` | `{label?, note?, content?, fromLive?:true}` (at least one) | `{ok:true, version:META}` |
| `activate` | POST | `slug, id` | `{mode?:"publish"|"draft", snapshotLabel?}` (default `publish`) | `{ok:true, rev, snapshotId?:string, active:id|null}` |
| `delete` | POST | `slug, id` | — | `{ok:true, active}` — 409 `active_version` when it is the active one |
| `purge` | POST | `slug` | — | `{ok:true}` removes the whole history file (idempotent) |

`META` = `{id,label,note,origin,createdAt,updatedAt,exportedAt,source,platform,widgets,bytes,locales,hasPublished,hasDraft,title,isActive}`
(`widgets` = widget count of the primary block (published, else draft), `bytes` = UTF-8 length of the
JSON of `content`, `locales` = sorted 2-letter locales found in localized values, `title` = the
version's localized title object, `isActive` = `id === active`). No `content` in META.

Error codes (`{"error":code, …}`): 400 `invalid_slug`, `invalid_id`, `invalid_body`, `invalid_content`
(+`detail`), `invalid_origin`, `invalid_mode`, `nothing_to_update`; 404 `not_found`; 409 `active_version`,
`too_many_versions`; 413 `version_too_large`; 500 `write_failed`.

### 3.1 `add`

Validates origin ∈ {import, capture, auto, manual}; `content` has ≥ 1 of published/draft, each a
JSON object holding `sections` (list) or `blocks` (list); title/nav localized values. Stores the
version. If `activate` is given: **in the same locked operation** do what `activate` does (below)
with the version just added; `snapshotId` is returned when a safety snapshot was taken. If the
activation fails the version is still stored and the answer is 500 `write_failed` with
`added:true,id` so the UI can say so.

### 3.2 `activate`

Under the site doc lock, then the history lock:
1. Read the live state as the admin sees it (`_load_site_admin` / `site_load_admin`).
2. **Safety snapshot**: if the page has a live state (published or draft present) and its normalized
   `{title, published, draft}` equals NO stored version's content, append a version
   `origin:"auto"`, `label = snapshotLabel || "Before activation"`. A snapshot that would exceed the
   limits makes the activation fail with the limit's error (nothing is changed — also when the
   version being activated was added by the same `add`: the whole request stores nothing). The live
   blocks are taken as they are (no gate, no clamping: a snapshot is never refused because the page is
   damaged; only a live title that is a valid localized object is kept — a legacy plain-string title is
   not). Titles take part in the comparison only where they can be lost: when the version activated
   carries a title different from the live one, a stored version must hold the live title too; a
   version without a title leaves the live title alone and is compared on its blocks.
3. Apply the version (mirror of `pageWrites`, same end state as an editor publish):
   * `publish`: `published = version.published ?? version.draft`; `draft = version.draft ?? published`
     (the editor always works on a draft); `title` = version title when non-empty, else unchanged;
     `schemaVersion = 2`. Written through the normal doc writers so the draft goes to
     `api/page-drafts/` and the public file carries no draft. `active = id`.
   * `draft`: only `draft = version.draft ?? version.published` and the title (published block
     untouched; created as `{"sections":[]}` when the page has none) — `active` unchanged.
   The blocks written pass the page-doc gate first (a version captured from a damaged page is kept but
   refused here with `invalid_content`, nothing moved). A publish whose files would not change (same
   blocks, title, private draft present, `schemaVersion` 2) writes nothing; a page still in the legacy
   layout (inline draft, no `schemaVersion`) is normalized by the write.
4. Answer `{ok, rev: site_rev(doc), snapshotId?, active}`.
Activating the already-active, unchanged version is a no-op write-wise but still succeeds.

### 3.3 `update`

`label`/`note` only change those and `updatedAt`. `content` replaces the version's content wholesale
(validated as in `add`). `fromLive:true` = replace the content with the page's current live state
(published + draft + title; `nav` kept as is). Both together are refused (400 `invalid_body`).

### 3.4 `delete`

Refuses the active version (409 `active_version`); the UI tells the operator to activate another
one first. Deleting the last remaining version removes the file.

## 4. Export / import file (`lumen-pages/2`, reader also accepts `/1`)

`pages-transfer.js` is the pure engine; **it is backward compatible** — every existing export of
`lumen-pages/1` keeps parsing. `tests/js/test_pages_transfer.mjs` was edited in 1.87.0 for what the new
format and the Import / export tab replace: `lumen-pages/2` is no longer "a newer format" (`/3` is),
the launcher's buttons lead to the tab (`navigateTo('pages-io')`), and the old export / import dialogs
with their `runImport` were removed (their media / variables helpers stay and are tested).

```json
{
  "$schema": "lumen-pages/2",
  "exportedAt": "2026-11-19T13:45:07.000Z",
  "platform": "1.87.0",
  "source": "bemine.be",
  "pages": [
    { "slug": "about", "title": {…}, "nav": {…}, "published": {…}, "draft": {…},
      "label": "Spring redesign", "note": "", "createdAt": "…ISO…", "active": true }
  ],
  "media": [ { "name", "type", "data" } ],
  "variables": { }
}
```

* A bundle is `/2` **only when some slug appears more than once** (= several versions of a page);
  otherwise it is written `/1` so older platforms can still read it. The optional per-entry
  fields `label`, `note`, `createdAt`, `active` are ignored by an older platform's reader and are always
  safe to write; this platform reads them in `/1` as well, so one version exported on its own (a `/1`
  file) comes back under its own name and note.
* In `/2` an entry = one version. Entries of the same slug are applied oldest `createdAt` first
  (file order when equal). At most one entry per slug carries `active:true`.
* In `/1` a repeated slug is still the `duplicate` error.
* Everything else (media, variables, limits, magic-byte checks) is unchanged.

### 4.1 File name

`exportFileName({ host, slugs, now })` → `<host>_<pages>_<ddMMyyHHmm>.json`
* `host` = `location.hostname`, lower-cased, a leading `www.` removed, anything outside
  `[a-z0-9.-]` replaced by `-`, trimmed of `-`; fallback `site`. (`bemine.be`, `localhost`.)
* `pages` = the slug when one page; several pages: slugs joined with `+` if the joined string is
  ≤ 40 chars, else `<n>-pages`. A single page exported with all its versions is still its slug.
* date = LOCAL time, zero-padded `dd MM yy HH mm` with no separators.
* extension `.json` (the importer accepts `.json` and the older `.lumen-pages.json`).

### 4.2 Compatibility verifier

Pure function in `pages-transfer.js`:
`checkCompatibility(bundle, site)` with `site = { platform:"1.86.0", widgetTypes: Iterable<string>, maxPageSchema: 2 }`
→ `{ ok, blockers:[{code,page?,detail}], warnings:[{code,page?,detail}], pages:[{index, ok, issues:[codes]}] }`.

| Code | Severity | Rule |
|---|---|---|
| `schemaNewer` | blocker (whole file) | `$schema` is `lumen-pages/N` with N > 2 (already `version` at parse time) |
| `platformNewer` | blocker (whole file) | `bundle.platform` is a valid semver strictly greater than `site.platform`. Message: exported by X, this site runs Y — update this site first |
| `siteUnknown` | blocker (whole file) | `site.platform` is not a version (the tab could not read this site's own): nothing can be compared, so nothing is imported (fail closed) |
| `widgetUnknown` | blocker (that page) | a widget `type` (walk published AND draft, legacy `blocks` too) is not in `site.widgetTypes`; `detail` lists the types |
| `pageSchemaNewer` | blocker (that page) | a raw page document whose `schemaVersion` > `site.maxPageSchema` |
| `platformUnknown` | warning | file has no/invalid `platform` |
| `platformOlder` | info-warning | file's platform < site's major.minor (nothing blocks) |
| `tokenUndefined` | warning | a `{token}` used by the pages is neither carried in `variables` nor … (reported by the UI with the site's own variables; the pure function only reports tokens absent from the bundle's `variables` and from `site.variables` when given) |
| `mediaMissing` | warning | already produced by `parseBundle` |

A blocked page cannot be selected for import; a whole-file blocker disables the Import button and is
shown first. Semver compare: numeric dotted `X.Y.Z` (missing parts 0, a `-suffix` ignored);
an unparsable `platform` is `platformUnknown`, never a blocker.

## 5. Import behaviour (UI contract)

Flow: pick or drop a file → `parseBundle` (structure) → `checkCompatibility` → **verification
report** (every check listed with ✓ / ⚠ / ✗, so "everything is good" is visible, not assumed) →
per-row choices → confirm → writes.

Per row (one row per entry; the entries of the same slug are grouped under one page heading):
* include checkbox; editable **target slug** (rename on import = "import under another name");
* **action**, default chosen from what exists:
  * target slug does not exist → `create` (new page; menu row added for a custom page, hidden unless published);
  * target exists → `version` (**default, safe**): add as a new version, the live page untouched;
  * target exists → `replace`: add as a version **and activate it** (publish or draft per the global
    option). The live state it replaces is kept by the server's safety snapshot, so **overwriting is
    never destructive**. A `confirm()` still lists which pages will be replaced.
* a global option **Activate imported pages: publish now / as draft** applies to `create`/`replace`.
* media: identical file reused, different file under the same name uploaded under the name the
  server picks and the pages follow (existing `planMedia`/`renameMediaRefs`); variables: absent ones
  added, conflicting ones kept and reported (existing `planVariables`).
* before writing, an open page-editor tab is told to stop autosaving (BroadcastChannel
  `lumen-page-editor`, `{t:'takeover', slug, id}`).
* Writes per entry, in order: media → variables → `add` (`origin:'import'`, label from file, else
  `<source> · <date>`) with `activate` when the action says so → menu rows.
  A failure of one entry never aborts the others; the result lists done / failed / notes.

## 6. The tab — `pages-io`

* Nav: group **Site public** (`data-group="site"`), right after *Pages*; `data-tab="pages-io"`,
  label key `admin.navPagesIO` (en "Page import / export", fr "Import / export de pages",
  es "Importar / exportar páginas", nl "Pagina's importeren / exporteren"). Registered in
  `admpan.js` like its siblings (lazy `import()`), panel `<section id="tab-pages-io">` in
  `admpan.html`, module `js/pages/admin/tab-pages-io.js` exporting `PagesIoTab`
  (`id`, `titleKey`, `titleDefault`, `mount`, `activate`, `relabel`, dirty-guard not needed).
* Top bar: **Import a file…** (+ drag-and-drop zone), **Export…** (choose pages, with/without
  history, with/without media), a *site version* chip (`v1.87.0`).
* **Page list**: one card per page — the built-in `home`/`about`, every custom page, and pages that
  only exist as a history (deleted: flagged *deleted page — restorable*). Card header: name, slug,
  live status chip (`In sync with "<label>"` / `Modified since "<label>"` / `Not versioned`),
  version count. The card is a collapsible drop-down (`<details>`-style, keyboard accessible,
  `aria-expanded`) listing the versions newest first.
* **Version row**: label, badges (`active`, `auto`, `import`, `capture`), date (local), widget count,
  locales, platform version it was made with (⚠ chip when newer than this site), size.
  Row actions (icon buttons with accessible names + a "more" menu on narrow widths):
  **Activate** (publish) · **Activate as draft** · **Rename** (inline) · **Edit note** ·
  **Export this version** · **Edit** (put it in the page's draft — through `activate` mode `draft` —
  then open the page editor `admpan.html?editor=<slug>`) · **Update from live page** (`update` with
  `fromLive`, confirm) · **Duplicate** (`add` origin `manual` copying the content) · **Delete**
  (confirm; the active one is refused with an explanation).
* **Page actions**: *Save current state as a version* (`add` origin `capture`, ask a label),
  *Export page (live)*, *Export with all versions*, *Delete history* (`purge`, confirm),
  *Open in editor*.
* All labels through `I18n` keys under `pagesIo.*` in `lang/{en,fr,es,nl}.json` (full parity).
  No user-facing technical text; server error codes map to translated sentences.
* Accessibility: every interactive control has an accessible name, focus is managed when a dialog
  opens/closes (`modalize` from `shared.js`), status changes go through an `aria-live` region / toast.
* Never put `err.message` in the DOM (CLAUDE.md v1.79.0): log with `console.error`.

The two buttons *Export* / *Import* of the Pages tab launcher now **switch to this tab** (one code
path, no divergent overwrite semantics); the old dialogs' exported helpers that tests import stay.

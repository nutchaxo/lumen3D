# Changelog v1.61.2 (Web Platform)

## [FIXED]

- **About and Explorer navigation bar**: the bar was painted with `--bg-base`, a token no theme defines, so it was transparent and the page scrolled visibly under the links (on About, the figures of the statistics band ran through the menu). It now has the page background of the active theme (`--bg-body`), as intended.
- **Active slice preset readable**: the selected XY / XZ / YZ button wrote its label in `--bg-base`, so the label took the sidebar text colour instead: light grey on the bright green in the dark theme (2.6:1), dark text on the dark green in the light theme (3.4:1). It now uses `--text-inverse`, the colour for text on a filled surface: 5.3:1 in the dark theme, 5.0:1 in the light theme.
- **Viewer surfaces drawn on the page background**: the channel cards, the timeline track, the measurement tiles and saved-measurement list, the related-dataset links of the 2D page, the dataset-card availability badges of the Explorer, the option buttons of confirmation dialogs, the gallery thumbnails, the tracking tools' segmented controls and inputs, and the sidebar title bar were all painted with `--bg-base`, so they had no background at all. They now sit on `--bg-body` as written: a darker well in the dark theme, a light grey one in the light theme, so a card, the timeline track or a tile reads as a surface instead of a bare outline. The tracking-surface select also gets back its arrow, which the invalid `background` shorthand was erasing (only its background colour is set now). The viewer root and the base Studio workspace rule take `--bg-body` too, which changes nothing on screen (the body has that background, and the Studio's own `#050607` rule wins).
- **Gallery lightbox picture**: the enlarged picture had the same undefined background; it is now left transparent on purpose, because the lightbox is a fixed dark stage in both themes and a light page background behind a transparent capture would wash it out.

## [ADDED]

- **Theme token guard**: `tests/test_css_theme_tokens.py` checks, page by page, that every `var(--token)` written without a fallback in a page's stylesheets, its `<style>` blocks and its inline `style=""` attributes names a property one of them declares. It found six more undefined tokens: `--border-light`, `--border-color` and `--bg-card` on the public pages, and `--text-muted`, `--z-viewer-base` and `--z-admin-overlay` on the admin page, which does not load the public stylesheets. These are listed as pending: the test fails when one of them is fixed and still listed, or when a new one appears. `--bg-base` stays undefined on purpose, as the page builder's widget-level override (`var(--bg-base, var(--bg-body))`).

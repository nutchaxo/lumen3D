# Changelog v1.62.0 (Web Platform)

## [ADDED]

- **Delete button with a 60-day trash**: every published dataset of the admin *Datasets* tab has a trash button (in its list row and in the editor header). A delete never erases bytes: the dataset's folder is moved (a rename, instant whatever the size) to `uploads/trash/<id>/data` with an `entry.json` (id, name, stage, deletion and expiry dates, size), disappears from the explorer and the catalog at once, and is reclaimed for good 60 days later. `uploads/` is never web-served and never touched by an update, so the trash is private and survives upgrades. A dataset still importing is not deletable here (the Import tab discards it).
- **Same name, any number of times**: each deletion is its own trash entry (`<type>__<folder>__<UTC stamp>-<random>`), so deleting a dataset, uploading a new one under the same name, finding it is no better and deleting that one too keeps both copies side by side in the trash, each restorable with its own bytes.
- **Trash dialog**: a trash button with a counter in the dataset list header opens the list of deleted datasets (name, id, deletion date, size, days left, highlighted in the last week) with *Restore*, *Delete permanently* and *Empty the trash*. Restoring over a dataset that has the same name meanwhile (it was re-uploaded) is refused by the server with a free suggestion (`name-restored`, `name-restored-2`…); the dialog offers to restore under that name, and the restored `metadata.json` is given the matching `id`.
- **Automatic expiry**: entries older than 60 days are reclaimed on every dataset list and trash list, on both backends (no cron needed); a half-written entry left by a killed delete is reclaimed after an hour.
- **API**: `api/datasets.php` (Python `dev_server.py` and PHP twins) gains `delete`, `trash_list`, `trash_restore`, `trash_purge` and `trash_empty`, the four writes behind POST + CSRF like every other write. Engine `dataset_trash.py`, PHP twin `api/_trash_lib.php`, same on-disk layout, so a host can move between the two backends and keep its trash. Shipped in the release (`tools/build_release.py`). Tests `tests/test_dataset_trash.py` (engine + the real HTTP handler) and `tests/test_dataset_trash_php.php`.

# Changelog v1.55.2 (Web Platform)

## [CHANGED]

- **The slice takes the main view while the slice tool is open**: the two renders trade places for as long as the *Slice through volume* tool is active. The GPU slice (`VolumeSlicer`) fills the canvas area — letterboxed, never stretched — and the WebGL canvas moves into the square of the inspector panel, where the plane is still dragged in 3D and the view still rotates; both canvases keep their contexts (a canvas re-parented inside one document is the same element), `VolumeViewer.resize()` follows the new parent, and everything goes back when the tool closes, with a camera distance the user did not touch restored (the square fit may have pushed it back). One page-level door, `viewer.js` `_setSliceStage`, driven by the slicer's visibility (`VolumeSlicer.onVisibleChange`): the tool, a sibling panel's `SYNC_SLICER_SPEC` and the Z-stack browser all share it. The staged slice renders at the displayed size in device pixels — up to 1024 px while the plane moves, and a sharper pass up to 2048 px once it has settled for 160 ms (`VolumeSlicer.setPreviewResolution(size, refineSize)`), so a drag never pays the big readback; the sidebar preview goes back to 320 px when the tool closes and the big render passes are released.
- **The slice tool and the Z-stack browser exclude each other**: both own the clip box and the main view, so opening one closes the other. Picking the slice tool (chip, shortcut `C`, a host's `SET_TOOL`, a restored workspace) closes the browser first — before the panel opens, so the browser's `resetClipping` cannot undo the plane; opening the browser (toolbar toggle, `TOGGLE_ZSTACK`, a sibling's `SYNC_ZSTACK_SLICE`, a restored workspace) leaves the slice tool through the `ToolManager`, drops a slice a sibling had put on the stage and hides the 3D plane. In a Compare panel the tool change is announced to the host as any shortcut is (`TOOL_CHANGED`), so the shared tool stays coherent.
- **Slice inspector reopens on the 3D plane of record**: when the tool opens, the slicer adopts the 3D plane (`VolumeViewer.getPlaneSpec()` — a restored workspace, a sibling's `SYNC_Z` or a reset all wrote it while the tool was off) instead of its own stale copy, with a plane parked on a face brought back to the middle; the sliders and preset buttons follow. The sibling-panel overlay (`#slicer-sync-overlay`, a 320 px canvas copied into a fullscreen canvas on every animation frame) is gone: a sibling's plane now goes on the same stage, at full resolution, and the Compare figure export reads the stage (`compare.js` `_visiblePanelCanvas`).
- **Plugins**: `slice-inspector` 1.1.0 (`activate()` toggles the ToolManager's `slice` instead of the chip-less `cut`; `platformCompat >=1.55.2`, the swap lives in the core) and `zstack-browser` 1.1.5 (the exclusion, optional-chained so an older ctx still opens the browser); both marketplace packages re-packaged and signed.

## [ADDED]

- **Exact scale bar on the staged slice**: the slicer draws `2·EXTENT` cube units across its square and, after its anisotropy scaling, one cube unit is the longest physical axis — the square spans `1.5 × max(x, y, z)` µm whatever the plane's orientation — so `#slice-stage-scale` shows a 1-2-5 bar computed from the displayed size (`_updateSliceStageScale`), hidden when the physical size is unknown. The 3D scale bar, which describes the camera now in the inset, is hidden meanwhile (`body.slice-staged`).
- **`VolumeSlicer` API**: `setPreviewResolution(size, refineSize)` / `getPreviewResolution()`, `flushPreview()` (the sharpest render, now — a screenshot taken on the stage captures it), `onVisibleChange(cb)`, `getPlaneExtentUnits()`. One render pass (target + readback buffer + `ImageData`) per size, at most two alive.
- **Caption under the inspector square** (`viewer.sliceInset3d`, four dictionaries): the square now holds the 3D view, with a grab cursor.

## [FIXED]

- **Moving a slice inspector slider reset the Z clip range**: the plugin's `_setSpec` called `ctx.viewer.setClipRange('z', spec)` with the plane object as the lower bound — `Number(object)` is `NaN`, clamped to `[0, 1]` — so every slider move silently restored the full Z range. The 3D plane mesh is now updated through the new `ctx.viewer.setPlaneSpec` only.
- **A saved workspace with the plane open did not reopen the tool**: `_applyWorkspaceStateNow` called `ToolManager.activate('cut')`, a tool name with no chip (`data-tool="slice"` is the chip; `cut` is what `VolumeViewer` alone calls it) and therefore a no-op. It activates `slice`, silently inside a panel (the host owns the shared tool). Same fix for the grab cursor rule in `css/tools.css`, keyed on `data-active-tool="cut"` and never matching.
- **Restoring a workspace erased the cut plane it had just restored**: `zstack-browser.setState({ zstackActive: false })` — applied by every restore, after the viewer state — went through the browser's close path, whose `resetClipping()` parks the plane on a face and hides it (and told the sibling panels to leave a stack they were not in). Closing a browser that is not open is now a no-op (`applyState` checks the previous state); a real close still resets the clip.
- **A restored or synced `xz` / `yz` / `xy` plane came back oblique, one degree off**: `VolumeViewer.setPlaneSpec` re-derived the plane from the `orientation` quaternion that every spec written by `getPlaneSpec()` carries, forcing `mode: 'oblique'` with a pitch of ±90° clamped to ±89°. A named mode defines its own orientation: the quaternion is applied to an oblique spec only. And an oblique plane came back with its yaw mirrored: `_applyOrientationToSpec` read the yaw as `atan2(n.x, n.z)` while the forward mapping (`Euler(-pitch, -yaw, roll, 'YXZ')`) gives `n.x = -cos(pitch)·sin(yaw)`; the inverse now decomposes the quaternion with the same Euler order, so a saved or synced oblique plane restores with its exact angles (round trip asserted numerically against the real Three.js in `tests/js/test_slice_stage.mjs`).
- **A sibling's `SYNC_Z` moved the 3D plane but not the slice**: the receiver only wrote the slider and the plane mesh; the staged slice and the slider label now follow too, with `notify: false` passed as an option (it was inside the spec, so the receiver re-broadcast the plane).
- **A sibling's plane spec leaked into the slicer**: `SYNC_SLICER_SPEC` merged the 3D plane's `visible`, `normal`, `orientation` and `axis` into the slicer's own spec, from where the next slider move pushed a stale `visible: false` back into `VolumeViewer.setPlaneSpec`. `VolumeSlicer.setPlaneSpec` keeps only the plane's own keys.

Tests: new `tests/js/test_slice_stage.mjs` (slicer resolution and refine pass, visibility events, plane-key whitelist, the exclusion in both plugins, structural checks of the swap, the restore path and the figure capture); `tests/js/test_viewer_postmessage_deadcode.mjs` asserts the overlay loop is gone.

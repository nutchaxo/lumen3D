# Changelog v1.54.1 (Web Platform)

## [FIXED]

- **A dataset whose orientation had just been defined on a PHP host no longer opened in the admin panel**: "Malformed dataset, mount refused (invalid type)", while the public site showed it correctly. The editor never posts `type` (the server owns it), and `api/datasets.php` wrote the posted body *verbatim* into `metadata.json`, so a single save was enough for the file to lose its `type`; the next `action=get` then failed the editor's validation (`validateDatasetMeta`). The public site, which derives the type from the directory, saw nothing. The PHP twin now merges like `dev_server.py` (`save_dataset_meta`): keys absent from the body survive, an explicit `null` erases (that is how the editor clears a block), `id` / `type` / `folderName` are re-asserted from the directory on every write, a posted `type` never wins, and `configured` / `lastModified` take the Python names (`_adminConfigured` is still read by the list). Both reads (`get_dataset_meta` in PHP, `_get_dataset` in Python) re-assert the type as well: a file already damaged comes back as is in the editor, and its next save repairs it on disk — nothing to do by hand on the host. Tests: `tests/test_datasets_save_php.php`, `tests/test_dataset_meta_identity.py`.
- **The slice mode of the Z-stack browser brought the volume back to the raw orientation of the Imaris file, not to the defined orientation**: `VolumeViewer.setView('xy')` reset the cube to the identity. The calibration (`metadata.orientation`, Q_base — the cube pose at which the reference axes of the specimen coincide with the world axes) is now registered by the core (`VolumeViewer.setFrameQuaternion`, from `viewer.js:_baseQuaternion`, independently of the plugin) and the axis-aligned views honour it. Such a view still looks along the requested voxel axis — these are the acquisition planes — but the rotation *about* the viewing axis is free, and it is chosen as close as possible to the defined frame: the pose is S·B, with B the rotation that brings the voxel axis onto the viewing axis and S the rotation about Z nearest to F·B⁻¹, i.e. the normalised projection `(0, 0, q.z, q.w)` (the one that maximises ⟨S, F·B⁻¹⟩; independent of the sign of the quaternion). A frame with no in-plane component (a half-turn about an axis of the XY plane) falls back to the identity instead of producing a NaN; without a calibration, the poses are exactly the former ones. The `3d` view returns to the home pose when a default view exists. Test: `tests/js/test_view_frame_spin.mjs` (raw poses, in-plane rotation reproduced exactly, a sweep proving no other rotation is closer, degenerate case, rotation lock, 3D view).

## [CHANGED]

- **The orientation axes no longer carry an anatomical nomenclature by default**: the six arms are called *Red 1 / Red 2* (±X), *Green 1 / Green 2* (±Y), *Blue 1 / Blue 2* (±Z) in the admin panel and are drawn `R1/R2`, `G1/G2`, `B1/B2` on the gizmo (plugin `orientation-axes` 1.2.0, the same glyphs in the four languages — RGB is universal in imaging; the operator renames). The **Default view** options are built on the same vocabulary — "*Red 1* facing the camera, *Green 1* up" (`admin.viewPreset`) — and quote the names the operator gives to the arms: renaming an axis updates the list at once, an emptied field falls back to the default name; the *Custom (captured view)* option is kept. The six presets are listed in arm order and their pair (facing / up) is checked against the plugin's `ORI_VIEW_PRESETS`, which remains the only implementation of the geometry. The storage keys do not change (`orientationAxes.labels/hidden` as `R/L/A/P/V/D`, `defaultView.preset` as `right/left/anterior/posterior/ventral/dorsal`): existing metadata stays valid and an arm already renamed keeps its name. "Anatomical frame" becomes "Reference frame". Keys added `admin.axisRed/axisGreen/axisBlue`, `admin.viewPreset`; the twelve anatomical keys (`axisAnterior`…`axisLeft`, `viewVentral`…`viewPosterior`) are removed from the four dictionaries. Administrator guides (§3.5 and the plugin table) updated in the four languages; marketplace package re-packaged and signed. Test: `tests/js/test_admin_orientation_labels.mjs`.

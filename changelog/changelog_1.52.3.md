# Changelog v1.52.3 (Plateforme Web)

## [ADDED]
* **Les notes de version du panneau admin sont rendues en Markdown.** L'onglet *Version & mises à jour* affichait le corps de la release GitHub (le fichier `changelog_X.Y.Z.md`) dans un bloc monospace brut, étoiles, dièses et accents graves compris. Un moteur Markdown maison (`js/pages/admin/markdown.js`, module ESM pur, sans dépendance — le CSP strict n'accepterait de toute façon aucune bibliothèque tierce) rend désormais les titres, les listes imbriquées (serrées ou aérées, cases à cocher), les citations, les blocs de code, les tableaux avec alignement, les filets, le gras / italique / barré / code en ligne, les liens, les autolinks et les échappements. Les sections `## [ADDED]` / `[OPTIMIZED]` / `[FIXED]` (et `[CHANGED]`, `[REMOVED]`, `[SECURITY]`, `[API]`…) deviennent des pastilles colorées sur un filet de section ; le titre `# Changelog vX.Y.Z` est omis (la carte nomme déjà la version) et les niveaux de titre sont décalés de deux crans pour ne jamais dépasser le titre de la page. La boîte s'ouvre repliée (340 px, fondu en bas) avec un bouton *Tout afficher* / *Réduire* qui n'apparaît que si les notes débordent réellement ; la date de publication GitHub (`publishedAt`, que les deux backends transmettaient déjà sans l'afficher) accompagne l'en-tête, formatée dans la langue du panneau. Clés i18n `admin.releaseNotesMore`, `admin.releaseNotesLess`, `admin.publishedOn` dans les quatre langues.

* **Sûreté du rendu, par construction.** Chaque caractère de la source passe par l'échappement HTML avant d'atteindre la sortie ; le HTML brut est affiché en texte (seuls `<br>`, `<kbd>`, `<sub>` et `<sup>` sans attribut passent en balises) ; un lien n'est émis que vers une destination `http(s)` ou `mailto:` — `javascript:`, `data:` et les chemins relatifs restent du texte —, toujours en `target="_blank" rel="noopener noreferrer"` ; une image devient un lien vers elle, le panneau ne chargeant jamais une ressource distante (`img-src 'self'`). L'entrée est plafonnée à 64 Kio, ce qui borne le balayage des emphases sur une entrée adverse. Test : `tests/js/test_admin_markdown.mjs` — structure, inline, vecteurs XSS, entrée adverse, et rendu de chaque changelog jamais publié (balises équilibrées, balises et attributs allowlistés, `href` sûrs, chaque en-tête `[TAG]` devenu pastille), plus la vérification que l'onglet passe bien par le moteur.

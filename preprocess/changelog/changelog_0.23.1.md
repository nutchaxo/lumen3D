# Changelog v0.23.1 (Preprocessing)

## [OPTIMIZED]

- **Formats 5 and 6 no longer build a throwaway format-4 pyramid**: step 2 writes level 0 only. `format5.write_tree` hands back the two levels still needed after packing (the coarsest, for histograms, and the thumbnail level) instead of deleting them. This saves a full extra pass over level 0 and the temporary disk of every intermediate level. Histograms are now computed on the format-5 coarsest level (display only).
- **YZ plane packs read a level in fewer passes**: the format 5/6 writer builds the YZ packs of several consecutive 64-column blocks from one sequential read of the level, holding at most 256 MiB per task, instead of one full pass over the level file per block. Very large native levels no longer re-read the whole file from disk dozens of times per channel and timepoint. The packs written are byte-identical.

## [FIXED]

- **Bleaching curves of sparse timelapses follow brightness, not the specimen's share of the frame**: each frame's signal level was the 99.9th percentile of every voxel. In a sparse series that value moved when cells divided or entered the field, and fell into the background below 0.1 % signal. Levels are now ranked over the voxels above the noise floor, the same rule as the series' white point. The basis is chosen once per channel and recorded as `intensityNormalization.signalBasis` (`2-image_processor.py` 0.15.1).
- **A busy dataset no longer costs a finished run**: publishing waits up to 2 minutes, with growing pauses, for the web server to finish reading the dataset's packs, since Windows refuses to rename a folder while a file inside it is open. If the dataset is still busy after that, the published dataset is left unchanged and the complete preparation is kept in `DATA_WEB/.unpublished_<type>__<folder>` instead of being deleted. The wait happens with the published folder whole: when one entry is busy (planes/ read by the Studio, mips/ by the z-stack browser), the entries already moved aside go back before the next try, so a viewer never finds bricks/ missing for the length of the wait. `run_preprocess.py --publish-staged <that folder>` publishes it without processing again, and the next successful run of that dataset deletes it. When the preparation cannot be moved there either, it stays in the run's `.temp_preprocess_<name>/stage/<type>/<folder>`, which `--publish-staged` now accepts too (the message used to name a path the option refused).
- **Ctrl+C only cleans up its own dataset**: a confirmed interrupt removes only the interrupted dataset's `.temp_preprocess_<name>` folder. It used to remove every `.temp_preprocess_*`, including the working tree of another pipeline run writing into the same `DATA_WEB`.
- **Tight stabilised display box for formats 4, 5 and 6**: when attaching a tracking, `registration.imageBoxUnionUm` is built from the bricks each timepoint actually stores, read from the format-4 `index.bin` or the lossless `ll` index of a format 5/6 tree. Only format-2 manifests were understood, so every tracked timelapse built since pipeline 0.21 fell back to the whole acquisition box, and the viewer's stabilised cube was several times larger than the specimen (`5-tracking_importer.py` 0.3.1).
- **A re-imported tracking no longer keeps the old stabilisation**: when the new analysis has no raw coordinates and no declared transforms, `metadata.json` gets an empty registration (`appliedToVolume: false`, no transforms), which the viewer reads as "no stabilisation"; a `null` would have been logged by the viewer as a malformed block on every open. The previous analysis' transforms used to stay, and the viewer warped the volume with them under tracks they no longer matched.
- **Re-processing with --with-downloads refreshes the download archive**: step 7 runs `build_download_bundles.py --refresh-web`, which rebuilds `<folder>_web.zip` and `README.txt` from the dataset just published. The `.ims` link, ImageJ TIFF and MIPs are rebuilt only when the source `.ims` is no longer the file they were made from. Every artefact used to be skipped as already present, so a re-processed dataset kept serving the previous run's bricks and metadata in its archive.
- **Download TIFF calibration follows the .ims unit**: the ImageJ/Fiji TIFF in a dataset's download folder converts the Imaris extent through its declared unit (mm, nm, m, µm), as `metadata.json` does. An extent in mm used to make the TIFF's voxel size 1000× wrong. When the `.ims` declares no usable extent or unit, the TIFF is marked uncalibrated (pixel units, as Image ▸ Show Info says) instead of claiming 1/N µm per voxel.
- **Embryo read after a dash-fraction stage**: `E8-5-2` now gives embryo Em2, like `E8.5-2` and `E85-2`. A stage written with the lab's dash fraction used to leave the embryo empty.
- **The standalone launcher carries format5.py and the current pipeline**: `run_preprocess.bat` embeds `format5.py`, which steps 2 to 4 import, and extracts it only where the repository's copy is absent. The committed launcher, which still ran pipeline 0.21.0, has been regenerated; a launcher built without `format5.py` would have failed every volume with ModuleNotFoundError on a PC without the repository. A test now fails when the committed launcher lags behind the pipeline sources.

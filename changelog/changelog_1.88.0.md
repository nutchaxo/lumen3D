## [ADDED]
- **Advanced Studio 1.3.0, image stacks**: a document is now an ImageJ ImagePlus with C channels × Z slices × T frames (ImageStack order, stack index `t·C·Z + z·C + c + 1`) instead of one plane per channel. Every plane is its own immutable array, so undo, the memory budget and the IndexedDB session store work per plane. Each plane is stored as its own Blob, so a stack far over Chromium's 133 MB value cap is saved and restored. Sessions written before stacks restore as 1 × 1 stacks with an unchanged journal replay.
- **Stack windows**: an image with slices or frames shows ImageJ's StackWindow controls under the picture. There is a `z` and a `t` slider with play buttons, and the animation speed and loop come from Image › Stacks › Animation Options. The subtitle (`c:2/3 z:36/72; … 8-bit; 54MB`) and the keys `<` `>` `,` `.` follow ImageJ. The status line gives ImageJ's `z=` coordinate.
- **Channel bar**: a multichannel image has a channel slider with one more position than it has channels. Position 0 (*c: all*) shows every channel as a composite, and the pixel read-out lists every value (`value=12,40,3`). Position k shows channel k alone and reads its value only. This was asked for by the user in place of ImageJ's `c` slider, so that the channels of a z-stack stay separate in one image and Split Channels stays possible.
- **Process Stack? like ImageJ**: a filter or pixel operation on a stack asks *Process all N images?* (Yes / No / Cancel), as ImageJ's `IJ.setupDialog` does. In a macro, the `stack` keyword answers Yes and its absence answers No. A multichannel image shown in Composite mode is processed whole (every channel and plane) with no question, and Yes on a multichannel image covers every channel. Every operation declares what it does on a stack and on RGB, taken from the flags of its ImageJ 1.54p class (138 operations, table `DOCS/studio-advanced/stacks/SWEEP.md`, checked by a test).
- **Image › Stacks, Hyperstacks, Type and Color menus**: 39 new commands with ImageJ's menu paths, dialog fields and macro keys.
  - Slices: Add / Delete Slice (slice, channel or frame), Next / Previous Slice, Set Slice, Images to Stack, Stack to Images, Make Montage, Reslice, Z Project, Plot Z-axis Profile, Label, Statistics, Measure Stack.
  - Animation: Start / Stop Animation and Animation Options.
  - Tools: Combine, Concatenate, Reduce, Reverse, Insert, Montage to Stack, Make Substack, Grouped Z Project, Remove Slice Labels, Set Label.
  - Hyperstacks: New Hyperstack, Stack to Hyperstack, Hyperstack to Stack, Re-order Hyperstack, Reduce Dimensionality, Make Subset.
  - Type: 8/16/32-bit of a stack, RGB Color, RGB Stack, HSB Stack, HSB (32-bit), Lab Stack, 8-bit Color (median cut).
  - Color: Stack to RGB, Make Composite, Split Channels and Merge Channels for stacks and RGB.
  Results are compared slice by slice with 554 golden cases recorded from ImageJ 1.54p (`tests/fixtures/ij-stacks/`, 478 files).
- **24-bit RGB images**: an RGB image is a document of three 8-bit planes shown as one picture, read out as `value=R,G,B`. Filters work per colour like a ColorProcessor. Measurements read the luminance with the weights of Edit › Options › Conversions (*Weighted RGB conversions*, `(int)(r·w + g·w + b·w + 0.5)`).
- **Commands that understand stacks**: Duplicate (range and hyperstack dialogs), Crop, Size (depth and time), Scale (Z and *Process entire stack*), Bin (Z shrink), Histogram (*Include all N images?*), Analyze Particles over the slices, Convert to Mask and Convert Stack to Binary, Threshold Apply, Image Calculator (stack × stack, stack × image, RGB). Measurements record the slice (`Slice`, `Frame` and `Ch` columns). A selection carries its stack position like `Roi.setPosition` and ROI Manager Show All draws it on its own slice.
- **Stack files**: TIFF read and write of multi-page stacks and hyperstacks, with ImageJ's description (channels, slices, frames, hyperstack, mode, spacing, frame interval, units) and its IJMetadata (slice labels, display ranges, LUTs). The writer is byte-identical to ImageJ for 25 of the 27 recorded files. The reader takes compressed (deflate, predictor) and planar files. RGB TIFF, PNG and JPEG open as 24-bit RGB. File › Save As › Jpeg… is new.
- **Open from Library as a stack**: File › Open from Library and the Z Project entry dialog offer *Stack (no projection)*. It loads the chosen slices as a real z-stack, with its channels as channels and the z step as voxel depth, from the original TIFF or the processed volume. A stack that does not fit the memory budget is refused with its size before anything is read.

## [FIXED]
- **Replays of stack commands act on the channel that was asked for**: Delete / Add Slice › channel, Reduce Dimensionality, RGB Color and the Z-axis profile read the channel the request named. They no longer read the engine's active channel, which is not journaled, so a recovered session cannot delete another channel.
- **RGB Color replays the picture the operator saw**: the display ranges, LUTs, mode and channels switched on are copied into the journaled parameters. A recovered session therefore gives the same pixels after a Brightness & Contrast change, and a channel switched off in the Channels tool is left out of the RGB image, as in ImageJ.
- **An image converted to RGB in place shows in colour**: its red, green and blue planes now get the Red, Green and Blue lookup tables. Before this fix they were drawn in grey, although the pixels were right.
- **A refused run without undo keeps the undo history**: a memory refusal before any plane changed no longer clears the undo steps or forces a snapshot of the whole stack.
- **Measure Stack stays on its image**: it stops with a message when another image becomes active, rather than mixing that image's rows into the Results.
- **Repeat Command follows ImageJ's Executer**: Next / Previous Slice and the animation commands can be repeated. Only Undo, Close and Repeat Command itself are not remembered, as ImageJ does.

## [CHANGED]
- **A multi-page TIFF without a description opens as a z-stack**, as in ImageJ. Before, its pages became channels.
- **Plugin requirement**: Advanced Studio 1.3.0 requires the core 1.88.0. All the stack code lives in the plugin (`ij-proc-stk.js`, `ij-cmds-stk.js` and the existing plugin files), and the core is unchanged.

# Changelog v1.55.0 (Web Platform)

## [ADDED]

- **Release notes of every version an update brings**: when a host skipped releases, the Updates tab shows one pill per new version, from the first one missing up to the version that will be installed (marked *will be installed*), and the notes of the selected one. Each release now ships `lumen3d-release-notes.json` (`tools/build_release.py`, listed in the signed `SHA256SUMS`, attached by `.github/workflows/release.yml`): every changelog of the flat `changelog/` directory in one file, so the panel reads the intermediate versions from one download instead of one GitHub call per version — the release body only ever carried the newest changelog, and a version that was never tagged has no body at all. `update_check` (Python + PHP twins: `_select_changelogs` / `admin_select_changelogs`, `_release_notes_bundle` / `admin_release_notes_bundle`) answers `changelogs: [{version, markdown}]`, oldest first, for `current < v ≤ latest`, with `changelogsSource: "asset" | "body"`; a release older than the asset falls back to its body, as before. Python caches the asset per tag in memory, PHP in `api/release-notes-cache.json` (never served, gitignored). Tests: `tests/test_release_notes.py`, `tests/test_release_notes_php.php`.
- **Release notes as a foldable tree**: the notes are rendered by `renderReleaseNotesTree` (`js/pages/admin/markdown.js`) as `## [TAG]` sections → entries → details, with native `<details>` elements (no script, CSP-safe). The default, folded view lists every entry by its title alone — the bold opening of `- **Title**: details`, the bold sentence the older files start with, or the text before the first colon — and *Show details* unfolds them all; *Titles only* folds them back. The box scrolls in both states (`max-height: min(60vh, 560px)`), so a long changelog never pushes the update button below the fold. Sections keep their badge and show their entry count. Test: `tests/js/test_admin_markdown.mjs` §6 (title split rules, tree structure, every changelog ever shipped folds into a balanced tree).
- **A dedicated release-notes page**: *Open in a page* opens `admpan.html?changelog=1` in its own browser tab (`js/pages/admin/tab-changelog.js`, the chrome-less shell the page editor already uses): every pending version, open, the target marked; then every installed version from `?action=changelog_history` (the local changelog files, newest first, the current one marked). Each version, each section and each entry folds on its own; *Expand all* / *Collapse all* act on the whole page.

## [CHANGED]

- **Changelogs are written in English**: from this version on, every `changelog/changelog_X.Y.Z.md` is in English, one entry per line in the form `- **Short title**: what changed and why` — the title is what the folded view shows. The two previous changelogs (v1.54.1, v1.54.2) are translated so the notes an update from v1.54.0 brings read the same, and the GitHub release notes of v1.54.2 are updated accordingly. Older changelogs keep their original French.
- **Updates tab wording**: *Show all* / *Collapse* become *Show details* / *Titles only*; new keys `admin.releaseNotesOpenPage`, `admin.releaseNotesTarget`, `admin.releaseNotesCount` and `admin.changelog*` in the four dictionaries.

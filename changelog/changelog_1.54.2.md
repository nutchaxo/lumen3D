# Changelog v1.54.2 (Web Platform)

## [FIXED]

- **The slice mode of the Z-stack browser looked at the stack from the wrong side**: the slices leave only two possible viewpoints, on either side of the voxel Z axis, and the one used until now (the +Z face toward the camera) showed the specimens mirrored with respect to the acquisition. The browser now asks for the opposite face: `VolumeViewer.setView(view, { side: 'back' })` — the front pose turned over by a half-turn about the vertical (`Ry(π)·S·B`), so the top of the screen names the same voxel direction on both sides and the image is the mirror of the previous view, exactly what turning the sample over does. The in-plane rotation stays the one chosen for the front face against the calibrated frame (v1.54.1); it is not recomputed from behind, because a half-turn about an axis of the plane has no Z component and every back pose would be equally far from a frame that faces forward — the choice would fall on the tilt, not on the defined orientation. Without a calibration, the pose is `Ry(π)`. Plugin `zstack-browser` 1.1.3 (marketplace package re-packaged). The Studio, for its part, still renders the Z-stack slice in the raw voxel frame (`VolumeSlicer` mode `xy`, required by the native per-slice pass): its figure may therefore differ from the screen by the in-plane rotation and by the side. Tests: `tests/js/test_view_frame_spin.mjs` (§6), `tests/js/test_zstack_slab.mjs`.

## [ADDED]

- **`metadata.json` files already damaged by a PHP host are repaired on disk automatically**: v1.54.1 reopened these datasets in the editor (the type is re-asserted on read) but only corrected the file at the next save. The identity pass of the one-shot migration (`_migrate_metadata` / `lumen_migration_metadata`: `type` = the directory, `id` = `<type>/<folder>`) is no longer conditioned on the presence of an old vocabulary: it runs at every start of `dev_server.py` and on the first PHP request that reaches `lumen_migrate_dataset_types()` (`catalog.php`, `datasets.php`, `upload.php`), and only rewrites the files that disagree with their folder — a sound file is neither rewritten nor reformatted. One read per dataset, which the catalog already does on every request. Tests: `tests/test_dataset_meta_identity.py` (repair at boot, idempotence, sound file untouched), `tests/test_repair_dataset_identity_php.php`.

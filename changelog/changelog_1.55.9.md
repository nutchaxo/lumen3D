# Changelog v1.55.9 (Web Platform)

## [CHANGED]

- **The sample-side switch previews the top face itself, and never touches a default view**: in v1.55.7/v1.55.8 the switch turned the current pose over on the admin preview and rewrote what the dataset opens on — first the calibration, then the default view. Neither depends on which side is up: the calibration maps file axes to anatomy and a default view is a pose of the anatomy the operator chose to open on. Both are now left alone, and the switch does one visible thing: the preview lays the volume flat with the face the switch names as the top toward the camera (`VolumeViewer.setSampleUpsideDown(flag, { preview: true })` → `setView('xy', { side: 'top', spin: 'tilt', animate: 1000 })`) — exactly what the Z-stack browser will show — so the operator picks the side by looking at that face, and what they verify in the viewer afterwards is computed by the same function from the same flag. The editor posts the switch and stores nothing but the flag (`SAMPLE_SIDE_RESULT` carries only the flag; `orientation-axes` 1.3.2 keeps its calibration and default view). The hint under the switch says what the preview shows.
- **Opening the Z-stack browser turns the volume about one screen axis**: the smallest-angle move of v1.55.7 rotated about an oblique axis and read as a diagonal tumble. The new `setView` spin `'tilt'` brings the stack's axis onto the viewing axis by a rotation about the screen axis it leans on most — the horizontal when the lean is mostly up/down, the vertical otherwise, ties included (a stack pointing straight away turns over about the vertical) — with a correction about the other axis that is never more than a quarter turn, and no in-plane turn at all; the animation grows both rotations together (`_tiltToViewAxis`, `_tiltPose`). Opening the browser and entering the track use it; the slider and a sibling's spin still turn in-plane. `zstack-browser` 1.2.1, `platformCompat >=1.55.9`.

Datasets whose side was switched on under v1.55.7 carry a calibration rewritten by that version (turned about the file's X axis); their anatomical views are off by a half-turn until the orientation is defined again in the editor.

Tests: `tests/js/test_view_frame_spin.mjs` §12 (the preview shows the top face, frame and home untouched) and §13 (`'tilt'`: lands flat, turns mostly about the primary screen axis with a slight correction, a flat stack is left alone, the two-axis animation path), `tests/js/test_sample_side.mjs` (plugin leaves calibration and default view alone, editor stores nothing, browser opens with `'tilt'`).

# Changelog v1.55.3 (Web Platform)

## [FIXED]

- **Black bands on the native slice of an oblique cut**: the Studio's native pass chose the LOD0 bricks to load by testing each brick against the plane's physical normal (yaw/pitch/roll), while the slicer samples the plane in texture space, where the physical anisotropy (`maxP/p_axis` on each axis) tilts an oblique plane's normal away from that one. The bricks the far ends of the cut actually cross were never loaded and rendered as black bands one chunk wide. The bricks are now picked in the slicer's own geometry (`VolumeSlicer.planeGeometry`, also the source of the shader's uniforms, so the two cannot drift): on the reference 3789² dataset an oblique cut crossed 3272 bricks of which the old test missed 836.
- **Native slice black at a brick boundary**: an axis-aligned cut chose its brick layer with `round(value × (dim − 1))` while the shader reads voxel `floor(value × dim)`; at a boundary (e.g. 64 % of a 100-slice stack, or 75 % across a 2048-voxel axis) the layer below was loaded and the whole native picture came out black. The layer is now derived exactly as the shader does, with one voxel of slack each side.
- **A chunk that fails to arrive no longer leaves a hole**: a pack fetch or decode that failed for good used to leave the brick black, silently. The pass now retries those bricks once after the rush, then keeps the preview's pixels wherever a brick is still missing and says so in the Studio (`studio.nativeMissing`, in the four languages) and in the slice status line.

## [ADDED]

- **Chunks land one by one in the Studio, as they do in the 3D view**: while the native pass streams, the Studio's picture is refreshed about twice a second with what has arrived — native where a chunk has landed, the preview elsewhere — instead of showing the preview for the whole transfer and swapping once at the end. The slice shader gained a fallback picture (`FALLBACK_TEX`: `VolumeSlicer.renderWithMaterial(…, { fallback: { canvas, rect } })` paints the preview wherever the atlas has no brick, and for a slab wherever any sample of it would miss one), so a partial atlas renders as a complete image; the Studio swaps only the picture (`setSliceResult(sr, { imageOnly: true })`), layers and calibration untouched. A refresh waits for a real batch of chunks (2 % of them, or two seconds), and never comes more often than a few times the previous render's own cost.

## [OPTIMIZED]

- **The native pass decodes and uploads only the voxel planes it samples**: a single cut reads one voxel plane of every brick it crosses, yet each brick was un-mosaicked in full (64 tiles), interleaved into RGBA in full (1 MiB) and uploaded in full. A task of `BrickLoader.loadBrickTasks` may now carry a `region` (a voxel box of the brick): the decode worker un-mosaics that box alone and reads back only the mosaic rows that hold it, the viewer interleaves that box alone, and `SVRManager.writeRgbaBrickRegion` uploads it into the slot. An axis-aligned cut costs three planes of each brick (one of slack each side; a Z-stack slab its slices plus one each side) — 48 KB per brick instead of 1 MiB on the main thread and the GPU. A brick requested as a box is never written to the decoded-brick cache, and a whole brick that comes back anyway (cache hit, raw transport, main-thread decode) is cut down on arrival. Oblique cuts still take whole bricks.
- **Only the shown crop is rendered and read back**: with the preview's frame known, the native pass renders the window of the frame the Studio shows (`renderWithMaterial(…, { window })` — the same pixels the full frame would give there) instead of the whole 5684² frame per refresh: a refresh reads back a few megabytes rather than 129 MB, and costs 10–25 ms after the one-time shader compile.
- **One slice shader compile per pass**: the slicer keeps the material it builds for a foreign atlas (and the fallback texture) between the renders of a pass instead of disposing and rebuilding it — and thereby releasing and recompiling the program — on every render; `VolumeSlicer.releaseForeign()` drops it when the pass ends.

## [CHANGED]

- **`VolumeSlicer.renderHighRes(size, overrides, window)`** takes an optional window of the frame; **`renderWithMaterial(material, spec, size, overrides, options)`** takes `{ fallback, window }`; **`planeGeometry(spec, physical)`** is public (the sampled plane's texture-space normal, centre, slab half-thickness and the shader's step vectors). The slice shader's `colorAt` returns `vec4` (alpha 1 when a brick backs the voxel).
- **Tests**: `tests/js/test_native_slice_geometry.mjs` (the geometry, the brick selection run from the viewer source on axis-aligned, boundary, slab and oblique cases, with a brute-force sampling of the shader's plane) and `tests/js/test_native_slice_region.mjs` (region decode, loader pass-through and cache rule, atlas sub-box upload); `test_zstack_slab.mjs` asserts the new contract of the native pass.
